在检查代码之前，先阅读我提供的《波浪理论详解》。

- 1 浪

- 3 浪

区分：


# 二、不要把“书中经验”错误升级成硬规则

把书中所有规则划分为：

```text
Hard Rule
Soft Guideline
Typical Relationship
Optional Observation
```

例如，如果书中写的是：

```text
“通常”
“经常”
“多数情况下”
“倾向于”
“常见”
```

就不能在程序里实现成：

```text
必须
否则 invalid
```

请专门寻找这种错误。

# 三、建立“书籍规则 → 代码实现”映射

请建立一张映射关系：

```text
书籍规则
↓
代码函数
↓
具体判断
↓
是否一致
```

例如：

| 书籍规则 | 代码位置 | 当前实现 | 结论 |
|---|---|---|---|
| 某规则 | validateImpulse() | xxx | 正确 / 部分正确 / 错误 / 未实现 |

每一个重要规则都尽量找到对应代码。

如果找不到：

```text
标记为：书中存在，但代码未实现
```

如果代码存在规则，但书中找不到依据：

```text
标记为：代码额外规则，需要确认来源
```

# 四、评审时区分三种“错误”

这是非常重要的。

发现问题时必须区分：

## A. 违反《波浪理论详解》

例如：

```text
书中明确禁止 X
代码却允许 X
```

这是理论实现错误。

---

## B. 符合书籍，但代码实现有 Bug

例如：

```text
书中公式正确
代码比例计算错误
```

这是程序实现错误。

---

## C. 书籍本身没有明确规定

例如：

某种特殊边界行情书里没有明确说明。

这种情况不要擅自判定代码错误。

请标记为：

```text
书籍未明确规定
```

然后可以补充：

```text
通用 Elliott Wave 理论中通常如何处理
```

但必须明确：

> 这是补充信息，不是本次程序正确性的主要判断依据。

# 五、先 Structure，再 Label

无论书中采用什么术语，检查程序时仍然重点确认：

程序是否先识别价格结构，再根据上下文赋予浪级角色。

推荐检查流程：

```text
Candles
↓
Pivot / Swing
↓
局部价格结构
↓
Structure Candidate
↓
父级上下文
↓
Wave Label
↓
Degree
↓
Parent-Child Validation
```

重点检查程序是否出现：

```text
先认定当前是 Wave 3
↓
再寻找支持 Wave 3 的条件
```

或者：

```text
先认定父级是 WXY
↓
再强行把下面结构解释成 W / X / Y
```

如果出现，请判断：

这是《波浪理论详解》要求的推导方式，

还是程序自身产生的 forced labeling。

# 六、检查父级和子级关系

不要简单要求程序“先父级”或者“先子级”。

检查是否形成下面这种双向关系：

```text
Bottom-up

Pivot
↓
局部结构
↓
子级结构
↓
父级候选
```

然后：

```text
Top-down

父级候选
↓
根据《波浪理论详解》的内部结构要求
↓
验证子级
```

最后：

```text
Parent
↕
Child
```

进行一致性检查。

# 七、重点检查“浪完成”是否符合书籍定义

从《波浪理论详解》中找出：

> 一浪到底在什么条件下才能认为完成。

然后检查代码。

必须区分：

```text
forming
potentially_complete
confirmed_complete
invalidated
```

如果书中没有这几个英文状态，可以按照书中的实际描述进行映射。

特别检查：

程序是否仅仅因为：

- 达到 Fibonacci 比例
- 达到价格目标
- 达到时间窗口
- 出现暂时高低点

就宣布：

```text
浪已经完成
```

如果书中没有这样的依据，应标记为问题。

# 八、重点检查 Fibonacci 的来源

所有 Fibonacci 数值，例如：

```text
0.236
0.382
0.5
0.618
0.786
1.0
1.272
1.618
2.618
```

不要默认认为全部属于规则。

请逐项检查：

```text
这个比例是否在《波浪理论详解》中出现？
```

然后分类：

```text
书中明确规则
书中常见比例
书中辅助参考
书中未出现
```

如果代码使用了书中未出现的比例：

不要立即说错误，

而是标记：

```text
额外经验规则
```

并说明它会不会影响最终数浪结果。

# 九、检查代码有没有超出书籍规则做“过度推断”

例如书里只说：

```text

```

```text

→ 当前就是 X
```

这种属于：

```text
Rule Overreach
```

请重点寻找。

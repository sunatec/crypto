# 分析起点与样本上限

2026-11-05，W8的8组44前缀已由用户报告PASS，任务6.2完成，正式入口默认显示及固定起点100根截断均已有用户通过报告。

近期模式默认取初次加载时最近5,000根（含加载时末根）。加载锚点与起始索引只初始化一次，运行中新K线沿原状态继续，不滚动丢掉早期输入后重新分段。近期模式的初始数量不是持续运行的总样本上限。重新加载或切换图表会建立新上下文，因此自动模式不承诺与不同加载时刻结果相同。

固定起点模式按K线开盘时间>=请求时刻接收；请求落在K线内部时从下一根开盘开始，不使用部分OHLC。原始可用起点晚于请求时刻显示历史不足。请求晚于全部已加载K线时等待，不制造有效起点。真实有效种子可能晚于接收起点，面板分别列出，不能把二者混同。

固定模式样本上限只统计已收盘且实际接收的原始K线。未收盘更新与同根重复收盘不占新名额。最后一个名额仍完整进入内核；达到数量先显示“样本上限已达”，后续已有收盘K线被拒绝时显示“样本已截断：后续K线未计算”。截断后保留旧状态，不滚动重设，也不把窗口结束当R完成。暂不提供自动恢复。

W8使用独立人工窗口预期及已存在I1 OHLC输入，共8组44前缀。运行node tools/chanlun/build-window-validation.mjs，生成tmp/chanlun/window-validation.pine及清单；需44根已收盘图表K线，预期PASS: W8, 44 prefixes。覆盖固定锚点继续增长、固定上限、短历史、缺失历史、未来起点、内部时刻对齐、开盘预览／收盘去重，以及真实调用窗口门控与生产调度的OHLC联动。每个前缀重载仅处理已见数据。

这些是合成上下文测试，不代表BTC/ETH六个固定feed窗口的回放／重载验收。旧T4与调度正式入口的用户通过记录保留原版本；新增窗口函数与面板须重新平台验证，进度23/43。

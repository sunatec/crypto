- 新增合成周线、角色失败、边界、含义映射及接入前后对照测试；README 已说明数据与搜索限制。

## 待确认的规范问题

规范要求 BTC 的完整驱动浪为 0 合规，并以 4 浪切入 1 浪作为典型原因。实际枚举 63 条后，原引擎会把虚拟价格 0 导致的百分比不可计算作为 §3.16 的失败；该结果不能证明相应候选违反了价格几何规则。

目前工作区仅对带 `virtual: true` 的价格 0 起点，把该百分比规则列为待定，原因明确保存。普通真实价格输入仍使用原行为。由此有 4 条完整推动读法未被其余现有规则否定：

| 起点 | P1 | P2 | P3 | P4 | ATH |
|---:|---:|---:|---:|---:|---:|
| 0 | 64899 | 15460 | 109358.01 | 74420.69 | 126296 |
| 0 | 69000 | 49050.01 | 109358.01 | 74420.69 | 126296 |
| 0 | 64899 | 49050.01 | 109358.01 | 74420.69 | 126296 |
| 0 | 69000 | 15460 | 109358.01 | 74420.69 | 126296 |

这些读法全部待定，不能宣称已确认；P4 均高于 P1，无法统一归因为 4 浪切入 1 浪。

建议修正规范的固定 BTC 0 合规预期，明确“虚拟价格 0 使百分比规则不可定义时列待定”，保留以上 4 条待定读法。另一选择是严格复用原引擎的不可计算即失败行为，撤销虚拟起点的待定处理，并如实披露实际排除原因。待用户确认后完成 1.2、3.4 与最终验收。

## 规范取舍结果（2026-10-05）

用户确认采用第三种做法：价格 0 虚拟起点那一浪的 §3.16 价格运动百分比按 **+∞** 计算（从 0 涨到任何正价的极限），规则「3 浪不能同时小于 1 浪和 5 浪」化为「3 浪不得小于 5 浪」照常判定。取代上文的「待定」处理；规范、设计与提案已更正（设计决策 3a），1.2、3.4 完成。

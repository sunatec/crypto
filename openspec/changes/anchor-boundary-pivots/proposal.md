# 提案：数浪范围锚定首尾（把起点极值与当前价纳入枢轴）

## Why

`detectPivots` 的主循环是 `for (i = lookback; i < len - lookback; i++)`，**首尾各 `lookback` 根K线永远不可能成为枢轴**；叠加 ATR 过滤，区间开头/结尾的重要极值会被整段丢弃。

实测（BTC-USD 1d，2025-10-06 起）：
- **全局最高价 126296.00 就在第 0 根（2025-10-06）**，但第一个被检测到的枢轴是 L107000@2025-10-10——**126296 及其后的整段初始下跌完全没进入数浪**。
- 末尾：最后一个枢轴是 L63158@2026-08-11，之后 08-12、08-13 两根（含"当前价"）也没算进去。

这违反书里的规范：**3.12「数浪从起点开始」**、**3.15「上升浪型起点是首根K线最低价、终点是末根K线最高价；下降浪型起点是首根K线最高价、终点是末根K线最低价」**。数浪应当**从区间起点的极值一直数到当前**，而不是从第一个 ATR 显著枢轴数到最后一个 ATR 显著枢轴。

## What Changes

在 `analyze-wave-manual.js` 内（不改老脚本）新增 `anchorBoundaryPivots(pivots, candles)`，在每个级别的枢轴检测结果上做**首尾锚定**，并在 `scanAtDegree` 与 `pivotsFine` 生成处调用：

1. **起点锚定**：取「首根K线 → 第一个检测枢轴」这段前导区间的极值，作为起始枢轴，类型与第一个真实枢轴相反（保证 H/L 交替）。BTC 例子里 → 前置 `H126296.00 @ 2025-10-06`，于是初始下跌 126296→107000 被纳入。
2. **终点锚定**：取「最后一个检测枢轴 → 末根K线」这段尾部区间：
   - 若价格沿最后枢轴方向继续创极值（最后是 L 又出现更低低点）→ **延伸/替换**最后一个枢轴为新极值；
   - 否则（价格反向）→ **追加**一个反向类型的枢轴（当前的摆动极值），使数浪抵达"当前"。
3. 起点/终点锚定后仍保证枢轴类型严格交替、无重复索引。

## Impact

- 修改：`analyze-wave-manual.js`（新增 `anchorBoundaryPivots` + 在 `scanAtDegree`、`pivotsFine` 处调用）。
- 影响面：所有级别的枢轴序列都将从区间起点极值跨到当前——更符合书的数浪规范，且可能让开头/结尾的浪型（如初始大跌）进入候选。
- 回归：既有 36 单测须全绿；新增首尾锚定用例；BTC-USD 1d 重跑确认 126296 进入级别枢轴、末端锚到最近K线。

## 非目标

- 不改 ATR 过滤/lookback 本身的中段行为（只处理首尾边界）。
- 不改度量层公式、否定法引擎、报告结构、CLI、老脚本。
- 不保证"126296 起点"一定让某个大浪型成为主选——只保证起点极值与当前价**被纳入枢轴序列**，后续是否成型仍由否定法按规则判定。

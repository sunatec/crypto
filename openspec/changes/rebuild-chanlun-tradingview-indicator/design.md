## Goals / Non-Goals

**Goals:**

- 每个核心判断对应规则 ID、来源或标明的工程约定，并有独立预期样例。
- 以确定性的逐 K 状态机处理形态、递归、确认与绘图，保留解释结构形成的研究信息。
- 只用当时可见数据；在相同 OHLC、规则版本、参数、起点下，回放前缀与重载结果一致。
- 交付可独立运行的 Pine v6 文件、中文说明、验证工具与真实平台验收记录。

**Non-Goals:**

- 首版不实现 MACD 面积、背驰分类、一二三类买卖点、警报、下单或策略回测。
- 不读取其他周期，不恢复单根 K 线内部成交顺序，不支持 Heikin Ashi、Renko 等合成图表。
- 不提供缺乏明确来源的宽笔/新笔/旧笔切换，不实现同级别分解的第二套模式。
- 不要求逐点复刻竞品，不承诺任意历史截取起点得到相同划分，不以盈亏评价形态正确性。
- 不修改现有 Elliott 波浪分析、行情缓存或顾问系统的算法和需求。

## Decisions

### 1. 先冻结规则与预期，再实现依赖它们的模块

新增 `docs/chanlun/rules.md`，按 `K-*`（包含）、`F-*`（分型）、`P-*`（笔）、`S-*`（段）、`N-*`（标准化）、`R-*`（递归）、`Z-*`（中枢）、`E-*`（工程约定）组织。每项记录判定前提、允许的输入状态、成立条件、失效条件、端点归属、最早可确认时刻及样例 ID。

来源分类固定为作者正文、作者后续澄清/更正、编者说明、工程约定。正文的后期补充须核对其适用语境，编者注不自动成为正文规则。未在这份资料中核实的社区命名不作为规则出处。

在初始化、等价极值、相等边界等原文未唯一指定的实现细节上，采用一套明确的工程约定，并单独列出。涉及第71/78/81课图形更正、走势完成与递归升层的规则，须先补齐图例及反例再冻结；证据不完整时保留候选，不用近似规则补成“确认”。这是一项模块实现前的研究门槛，不新增产品模式。

备选方案是直接修改旧脚本或同时维护多种流派。选择独立规则表和单一口径，可以分离旧假设，减少组合验证成本。

### 2. 一份独立 Pine 文件，计算内核与展示分开

正式交付不依赖外部 Pine 库或 Node 服务。文件按输入、类型、核心计算、状态推进、绘图和研究输出分区；核心函数接收显式数据与状态，不直接读未来历史偏移或依赖绘图对象。

```text
当前图表 OHLC
  → 顺序包含处理 → 分型候选/确认 → 笔候选/确认
  → 标准特征序列 → 线段候选/确认
  → 标准化 L0 部件
  → L1 走势与中枢 → 已完成 L1 → L2 → 已完成 L2 → L3
  → 独立绘图注册表及研究视图
```

使用 Pine 用户类型和有界数组组织对象，避免旧脚本中多组平行数组索引错配。以时间、规则版本和依赖关系生成稳定逻辑 ID；`bar_index` 仅用于当前运行中的定位，不作为跨重载比较身份。价格比较使用标的 tick 精度，时间使用 UTC 毫秒。

基础记录包含：

| 对象 | 必备信息 |
| --- | --- |
| 合并 K 线 | 原始时间跨度、合并方向、高低点及各自来源时间、是否仍可能继续合并 |
| 分型/笔/线段 | 方向、起止点、输入 ID、候选/确认状态、端点时间、确认时间、规则 ID |
| 标准化部件 | 原线段 ID、真实分段端点、内部实际高低点、用于上层分析的端点及对应关系 |
| 中枢 | 层级、构成部件、固定核心 ZD/ZG、Z 波动统计、延伸范围、离开/回试/新生/扩展证据 |
| 走势 | 层级、子走势/中枢、范围、方向和形态、进行中/完成、完成证明及确认时间 |
| 绘图记录 | 逻辑 ID 到 line/box/label 的映射；不参与形态判定 |

### 3. 包含、分型和成笔按处理后的结构判定

- 含包含关系的 K 线按出现次序合并，再与下一根比较。向上取高点较高值、低点较高值；向下取高点较低值、低点较低值。方向来自此前非包含关系，不以被包含的新 K 线临时猜方向。
- 初始缺少定向依据时等待。工程约定：第一组相邻非包含输入确定种子和方向，此前前缀记为初始化区，不输出确认结构；同时记录实际有效起点。
- 分型要求中间处理后 K 线的高低点同时高于或同时低于两侧。右侧 K 线可能继续被合并时，相关分型仍为候选，不能把原始 K 线收盘等同于分型永久锁定。
- 成笔检查顶底交替、两个分型之间独立 K 线的归属及顶底区间条件。使用处理后元素的身份和成员关系，不用原始 `bar_index` 差代替独立 K 线条件。
- 同类分型按第77课的极值和顺序处理；等价极值优先保留先出现者，来源时间同步保留。末笔在满足后续锁定条件前允许延伸，已经锁定的前缀端点保持稳定。
- 工程约定：区间按闭区间处理，单点接触与严格分离分开记录；相等边界不得在不同模块随意改成严格不等式。零宽度中枢标为退化区间并以边界线显示，不通过额外最小振幅阈值改变规则。冻结规则表时须核对此约定与正文及更正的适用性。

### 4. 线段实现标准特征序列及两类终结

向上线段取向下笔、向下线段取向上笔，建立特征元素，按规则处理包含后识别所需分型。

1. 起始三笔必须有重叠，完整段的笔数及端点类型符合原文条件。
2. 特征分型第一、第二元素无缺口时，满足第一类终结，在对应极值定位端点，并以当时可见证据记录确认时间。
3. 存在缺口时先记为第二类候选，等待从候选端点开始的反向特征序列出现所需分型。第二次判断不再要求补掉第一处缺口，也不再递归区分第一/第二类。
4. 第71/78课对假设分界点两侧包含处理的差异单独实现，并按第81课图例更正核对。

特征序列状态、假设分界点、缺口和第二序列都保留研究信息。反向一笔或单纯突破不直接确认成段。尚未确认的尾部可能包含多个相互依赖的候选段，因此回滚范围按依赖确定，不固定为“最后一笔”。

### 5. 标准化线段启动自然递归，走势完成独立于中枢形成

原始线段供用户查看；按第78课构造的标准化部件供 L1 计算，保留两者端点对应关系。L0 不产生对外宣称的时间级别。L1 消费已确认 L0，L2/L3 只消费已完成下层走势。三笔重叠不作为正式递归中枢输入。

中枢与走势采用两套相连状态机：

| 状态/事件 | 行为 |
| --- | --- |
| 部件不足/三部件无公共区间 | 保留走势候选，不补造中枢 |
| 三个合规已完成下层部件重叠 | 建立中枢核心 ZD/ZG，记录各部件及确认时间 |
| 延伸 | 核心区间保持；按原文 Z 波动及重叠条件推进范围和统计 |
| 离开、回试待定 | 记录已完成离开部件与回试证据；不在第一次越界时结束中枢或走势 |
| 回试结束并脱离 | 记录中枢结束证据，继续判断新中枢或趋势；中枢结束不自动结束整个走势 |
| 新中枢与前中枢关系确定 | 分别比较核心和完整 Z 波动范围，判别趋势延续或高级别中枢扩展 |
| 当前层走势完成条件成立 | 锁定端点、子结构归属和完成证明，且仅在该确认时刻向上一层发送一次完成事件 |

核心上下界与整个波动范围分开存储。按原文中心定理维护 `GG/G/D/DD` 等 Z 波动统计，不把全部几何边界简单混成一个框；核心区间分离且完整波动范围同向分离与波动范围重叠分别进入趋势和升级分支。扩展后的上层对象保留下层来源，不删除或改写已经确认的下层结构。

走势完成的充分条件、最终极值归属和新走势起点复用方式，必须在 `R-*` 规则表中以原文及标明的工程约定给出有限状态转移与独立样例，作为递归代码的前置验收项。禁止以“刚形成一个中枢”“固定三段一组”“数据窗口结束”代替完成证明。首版自然递归持续处理延伸和扩展，不混入忽略延伸的同级别分解模式。

单层缺少完成证据时只输出该层候选，上层等待。L1～L3 为首版上限，参数可选择 1～3；达到上限时提示更高层未计算，数据不足也明确标注。

### 5a. 连续中枢的有限归属约定（2026-11-04）

中枢形成与R完成分别推进。E-010以真实终点识别离开候选，下一已确认L0自身实际区间触及核心时归入原中枢；严格离开时单列离开／回试证明，从回试部件重新寻找三部件公共区间。未定归属的连接段不提前混入旧中枢GG/DD；形成第三部件仍为必要来源。此为明确的工程口径，不声称正文唯一指定了软件归属算法。

每个中枢形成事件保存当时快照，关闭事件保存归属结束快照；两者均不被后续更新改写。新中枢的GG/DD仍会随延伸变化，因此相邻中枢的延续／扩展关系是带时刻的当前证据，不作为R完成承诺。中枢来源预算不足时整个输入原子回滚。保留最近15个关闭快照供显示、最新前中枢供关系计算、累计编号不随裁剪重置。R最终归属与上层提交门槛维持原契约。

### 6. 已确认前缀与可变尾部分离，按收盘提交

已确认指该结构按规则满足锁定条件，而不是“当前 K 线已收盘”。未锁定的成形结构仍按候选展示。已确认端点、确认时间和依赖 ID 只追加不修改；正在延伸的中枢可继续增加时间范围，走势可继续发展，这与已锁定端点稳定是不同属性。

- 历史 K 线逐根推进正式状态。
- 未收盘实时 K 线从上一收盘提交状态建立可变尾部预览，重复 tick 更新同一预览，不重复追加正式输入。
- 在 `barstate.isconfirmed` 时将当根输入及其引起的合法转移提交一次。正常结构状态不依赖 `varip` 保存只有实时 tick 才有的信息。
- 下一 tick 从正式状态重建尾部，失效候选可撤销；正式状态不消费预览层输出。
- 将端点发生时间与证据齐备的确认时间分别保存。绘图可以连向过去端点，但研究标记显示确认时刻，验证按确认时刻核对事件可用性。

避免每根 K 线全量重算整个 5,000 根窗口。正常运行采用增量状态、已确认前缀摘要及有限候选尾部；用于预览的复制必须为独立副本，避免 Pine 引用对象的浅拷贝污染正式状态。禁止用一次性 `calculated` 标志停止后续行情计算。

### 7. 区分计算起点、数据保留与绘图额度

默认初次加载取当时最近最多 5,000 根作为分析窗口，记录请求起点、有效种子起点和规则版本。运行中继续推进当时建立的状态；达到原始 K 线保留上限时，用确认摘要和未完成依赖管理存储，不能因为移除最早 K 线就悄悄重新初始化。保留完成结构的必要汇总，不无限存储全部细节。

自动窗口在重新加载、推进回放或交易所修订数据后可能改变起点；这是新的分析上下文。提供固定起始时间用于复现和验收，并以显式数据上限截断状态与提示结束，不在达到上限后滑动重设起点。回放中自动窗口起点可能变化，因此一致性测试必须使用固定起点；输入不足时显示实际范围。

资源工程初值：声明最多 500 个线、框、标签，管理器保留安全余量；默认图形预算为最近 150 笔、60 线段、每层 30 条走势与 15 个中枢，研究标签全局最多 120 个。预览、退化中枢边界线、确认标记等共用相同总预算。设置高低水位后先回收最老的可见对象，不能等待平台自动回收关键对象。预算初值可在平台性能验证后下调，并同步文档。

默认保留的绘图数量不决定计算结果。关闭显示层、调颜色或回收旧图形不得修改结构状态；必要依赖尚未释放而计算预算将超限时，显式提示受限层级并停止该层的确认/上报，保留已确认结果，不回退简化算法伪造完成。恢复须显式重新加载或扩大支持范围，并记录上下文变化。无需确认数据时，独立控制临时数组和候选数量，避免超时后才被动失败。

对较早时间端点使用 `xloc.bar_time`，不依赖超出允许范围的 `bar_index` 绘图。历史数组访问使用数据内索引，不能把绝对 K 线编号当作 series 历史偏移。

### 8. 看盘与研究共用同一结果模型

默认中文界面：笔蓝色、线段橙色，L1 走势紫色，L2/L3 使用与前述层次可区分的颜色；同层走势、中枢边界和结构标签使用对应色系，中枢浅填充。笔线较细，段与上层走势逐级突出。候选虚线、候选框虚边；已确认实线。颜色、线宽、中枢透明度和提示字号可调，层级开关控制可见性。显示起点、结构状态、层级含义和数据/资源不足状态。

研究开关按需展示分型编号、合并 K 线范围、特征序列、缺口、规则 ID、真实/标准化端点和确认标记。低周期映射、竞品兼容、背驰和买卖点不出现在首版设置中。

用户指定的展示基线是 [日文发布页](https://jp.tradingview.com/script/L0Xy7qaL/) 与同一脚本 ID 的公开示例图。2026-11-01 已查看其原尺寸预览：上证综合指数、SSE、日线、约2018年下半年至2023年5月。图中蓝色细线、橙色中层线、紫色长跨度线与浅蓝/浅橙框构成视觉层次。它是历史静态示例，不是 BTC/ETH 验收样本，不能据它推断实时确认和撤销行为。图片 URL、内容哈希、页面说明差异及观察边界保存在 `docs/chanlun/reference-comparison.md`。

| 字号和可见性控制 | 独立层开关、可调字号、线宽和中枢透明度，沿用统一对象预算 | 首版；在普通与研究视图分别核对可读性 |
| 圈号样式 | 只参考定位和视觉形式；其方向、形态或信号语义按页面证据分别记录 | 资料参考；不把实心/空心圈号猜作确认/候选状态 |
| 端点 MACD 面积与背驰 | 待规则和形态底座验证后，单独定义计算区间和比较条件 | 后续阶段，本次不提前画数值占位 |
| 三类买卖点及警报 | 后续按原文和确认时刻建立独立信号模块及提醒设置 | 后续阶段，本次不展示假信号或未实现参数 |
| 多种笔段规则 | 记录竞品配置能力，本项目首版仍固定一套来源明确的规则 | 仅作参考，不复制缺少定义的模式 |

页面文字与图片对某些颜色/语义并不完全一致，故保存“图像观察、作者说明、本项目选择”三列，避免将展示相似误当作算法相同。默认看盘视图与研究视图分别保存实际渲染证据，检查线条层级、K 线是否被遮挡、同层配色、标签密度和字号。展示验收与时价端点/确认时刻的计算验收分别记录。

### 9. 用原文预期验证实际 Pine 内核

`tests/fixtures/chanlun/` 保存机器可读样例：规则 ID、来源分类及定位、OHLC 或已确认低层部件、预期结构和逐前缀事件、构造说明。人工推导的预期不得从待测实现自动回填；原文图例只存必要的结构标注和出处，不假装从无数据的图片还原精确 OHLC。标明后期已更正的原图对应关系。

`tools/chanlun/` 将选定样例与正式 `.pine` 中同一核心函数区组合为独立验证脚本；使用离线生成的完整 Pine 文件，不引入运行时库。样例逐元素注入，按每个前缀核对端点、状态、层级和确认时间；失败以明确错误及样例 ID 呈现，成功给出检查摘要。生产与验证入口共用提取出的同一内核，避免另写一份 JS 算法成为唯一“正确答案”。

验证分三组：

1. **规则样例**：包含方向与链式合并、相等极值、分型未封口、原始间距足够但合并后无法成笔、线段两类终结、假设分界包含、标准化、中枢延伸/新生/扩展、走势未完成不升层。
2. **因果和生命周期**：对同一数据的每个前缀保留确认事件；比较在线逐步推进与该前缀重新初始化的结果；实时多 tick 预览不得污染正式状态、重复输入不得重复确认、锁定端点不被后来数据移动。
3. **平台行情**：固定 `BINANCE:BTCUSDT` 与 `BINANCE:ETHUSDT` 的 60、240、D 六个组合，记录 feed、图表类型、UTC 起止时间、实际 OHLC、tick 精度、参数、规则/脚本版本和平台环境；对每组记录编译、加载、回放、重载及状态证据。其他来源数据只有核对 OHLC 一致后才能作同一基准。

固定行情若没有某种罕见结构，使用人工边界样例补覆盖；不要求为了通过验收强行生成所有三层。研究数值、Pine 日志/验证脚本断言和图表记录共同作为证据。离线生成成功不等同平台编译通过，历史回放也不替代真实未收盘多 tick 检查。

新增 `docs/chanlun/validation.md` 记录每组的命令、预期、实际、通过/失败/尚未执行状态和证据路径；`docs/chanlun/reference-comparison.md` 记录可访问的竞品版本、设置、数据范围及观察差异。竞品不可访问或设置不一致时如实记录，原文规则与回放验收继续执行。

## Risks / Trade-offs

- [选编本含编者说明和遗漏图] → 源规则分类、回到 PDF 图像核对、更正优先适用，图像重建样例标明其合成性质。
- [走势完成与合法结合存在解释空间] → 先冻结单一自然递归转移表和反例；证据不足保留候选；不声称该工程约定是原文唯一分解。
- [等待锁定会推迟结构确认] → 实线/虚线和发生/确认时间同时表达；首版不使用候选输出交易提醒。
- [当前周期不能恢复内部成交顺序] → 明示数据粒度及有效起点；不承诺与逐笔或跨周期结果相同。
- [自动窗口变化影响重载对照] → 验收固定起点和 OHLC，窗口或行情修订时显示上下文变化。
- [Pine 计算/绘图配额和引用对象 rollback] → 增量更新、有界依赖、独立预览副本、集中对象管理与平台压力验证；受限时停止受影响层级上报并明示。
- [离线无法证明真实 Pine 行为] → 把编辑器编译、六组行情和实时 tick 检查设为交付门槛；无证据项目保留未完成。

## Migration Plan

1. 规则与验证材料、新入口并行开发；两份旧 Pine 原样保留在根目录，作为历史对照。
2. 完成新指标的规则、因果、资源和 TradingView 验收，记录实际结果后将新入口标为正式。
3. 用内容校验确认归档副本与旧文件一致，将两份旧 Pine 原样迁到 `archive/chanlun/`，附历史原型说明；保留根摘录与书籍，更新 README 引用。
4. 若新版验收失败，保留其候选身份及失败记录，旧文件继续原位；已经迁移后需要恢复时，从归档原样恢复并标注旧版局限，不混合两套状态或规则。

本变更只生成提案及规格时不移动旧文件、不修改现有运行脚本。归档执行属于本变更后续实现任务的最后阶段。

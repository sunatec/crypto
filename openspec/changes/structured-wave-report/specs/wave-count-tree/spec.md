# wave-count-tree

## ADDED Requirements

### Requirement: 结构化波浪分析报告（7 节，自然语言，不替换现有报告）
引擎 SHALL 能产出一份固定 7 节的结构化 Markdown 报告：① 分析范围 ② 关键转折点 ③ 已完成浪型
④ 当前主方案 ⑤ 备选方案 ⑥ 方案排序 ⑦ 最终话术。该报告经 CLI 开关产出，现有报告 MUST 保留、
不被替换。所有日期、价格、浪型 MUST 由本次 K 线计算，不得使用示例中的占位数字。

#### Scenario: 七节结构齐备
- **WHEN** 以结构化报告开关运行引擎
- **THEN** 输出的 Markdown 依次含"分析范围/关键转折点/已完成浪型/当前主方案/备选方案/方案排序/
  最终分析话术"七节，且现有默认报告仍可照常产出

#### Scenario: 关键转折点带暂定浪型位置
- **WHEN** 渲染第 2 节关键转折点表
- **THEN** 每个转折点给出 序号/日期/价格/类型，并标注其在主方案里的**暂定浪型位置**（第几浪）

### Requirement: W-X-Y（或所选结构）必须逐腿展开并给出排除理由
当已完成结构被判为 W-X-Y（或任何多段结构）时，第 3 节 MUST 逐一说明每一浪的起止时间与价格、
各自的内部结构、价格比例与时间比例，并给出"为何是该结构、为何不是单锯齿/五浪推动/平台形"的
对比理由（依据各竞争形态的具体违规）。MUST NOT 只写"从 A 到 B 看作 W-X-Y"而不展开。

#### Scenario: W-X-Y 逐腿 + 排除理由
- **WHEN** 主方案为 W-X-Y
- **THEN** 报告分别给出 W/X/Y 的起止(时间+价格)、内部结构、价格比例、时间比例，并说明它比
  单锯齿/五浪推动/平台形更合的具体理由（引用那些形态各自的违规）

### Requirement: 最后一个转折点之后的多方案评估与"修正对象"
第 4/5 节 MUST 同台评估最后一个主要转折点之后行情的多个方案（至少：XX 反弹、更大级别 B 反弹、
新推动 1 浪、新推动 3 浪），且 MUST NOT 因涨幅大直接判 3 浪——判 3 浪前 MUST 逐条做书内结构
验证（存在第1浪、合规第2浪、第2浪未破第1浪起点、突破第1浪高点、内部五浪、突破前一轮关键结构
高点），不引入书外动量指标。每个反弹方案 MUST 说明它**修正哪一段**：XX 对应上一子浪、更大级别
B 对应整段完整结构，并给各自的目标区间。

#### Scenario: 3 浪需逐条结构验证
- **WHEN** 评估"新推动 3 浪"方案
- **THEN** 报告逐条列出书内结构验证项的通过/未通过，仅当关键项通过才提升该方案强弱档；
  不因涨幅大而直接判 3 浪；不使用 RSI/动量等书外指标

#### Scenario: 反弹方案必须点明修正对象
- **WHEN** 当前上涨被列为 XX 或更大级别 B
- **THEN** 报告分别写明：XX 修正的是上一子浪（如 Y=某段），B 修正的是整段完整结构（如全段
  下跌），并各自给出按书中回撤规则算出的目标区间——不得只写"可能是 XX 或 B"而不点明修正对象

### Requirement: 方案排序用高/中/低档而非概率百分比
第 6 节方案排序表 MUST NOT 给出统计概率百分比。SHALL 用高/中/低三档表示相对强弱（由违规数、
越界程度、未完成度客观分档），并给每个方案的支持依据、不利因素、确认条件。

#### Scenario: 排序表为高中低档
- **WHEN** 渲染第 6 节
- **THEN** 每个方案标高/中/低档（非百分比），并列出支持依据、不利因素、确认条件

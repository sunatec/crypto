## ADDED Requirements

### Requirement: 子浪角色须为书中规定的具体形态
引擎 MUST 按形态的子浪位置校验子腿的**具体形态**，而不只是「驱动 / 调整」类别。各位置允许的形态如下：

- 双锯齿、三锯齿的 w、y、z 腿 MUST 为单锯齿；x、xx 腿可为任意调整浪。
- 双重、三重横向整理（联合形）的 w、y、z 腿 MUST 为简单调整浪（单锯齿、平台形各子类、收缩三角形），MUST NOT 为双锯齿、三锯齿或联合形；x、xx 腿可为任意调整浪。
- 单锯齿的 a 浪 MUST 为推动浪或引导楔形；c 浪 MUST 为推动浪或终结楔形；当 a 浪只能读作引导楔形且 c 浪只能读作终结楔形时，SHALL 记一次文法违规。
- 平台形（含规则、扩散、顺势子类）的 c 浪 MUST 为推动浪或终结楔形。
- 推动浪的第 1 浪 MUST 为推动浪或引导楔形，第 3 浪 MUST 为推动浪，第 5 浪 MUST 为推动浪或终结楔形。

子腿「胜任」某位置 = 在该位置允许的形态集合内存在规则全过（tier1 = 0）的拆解。不胜任时 SHALL 计一次文法违规并入父级 tier1。
子腿点数不足以成形该位置任何允许形态时 SHALL 作为叶子处理，不计违规（数据不足不证伪）。
顶层数法（`decompose`）与用户数法打分（`evaluateExplicitCount`）MUST 使用同一套位置判定。

违规描述 MUST 指明所需形态与实测最接近的形态（如「w 须为单锯齿，实测为双锯齿」）。依据 Frost & Prechter 而非仓库书稿补足的规则（推动浪 1/3/5 浪位置），描述 SHALL 标注「（EWP）」。

#### Scenario: 双锯齿的 w 腿本身是双锯齿
- **WHEN** 某候选为双锯齿，其 w 腿在调整类形态中只能以双锯齿规则全过、无法以单锯齿规则全过
- **THEN** 该候选记一次文法违规，不得标为「✅ 规则全过」，违规原因写明「w 须为单锯齿」

#### Scenario: 双锯齿的 w、y 腿均为单锯齿
- **WHEN** 某候选为双锯齿，其 w、y 腿均能以单锯齿规则全过，x 腿为任意调整浪
- **THEN** 该候选不因子浪形态记文法违规

#### Scenario: 联合形套联合形
- **WHEN** 某候选为双重横向整理，其 y 腿只能以双重横向整理或双锯齿规则全过
- **THEN** 该候选记一次文法违规，违规原因写明「y 须为简单调整浪」

#### Scenario: 联合形的 x 腿为联合形
- **WHEN** 某候选为双重横向整理，其 x 腿为双锯齿
- **THEN** 不因 x 腿记文法违规（x 可为任意调整浪）

#### Scenario: 歧义腿在所需位置有干净读法
- **WHEN** 双锯齿的 w 腿既能以单锯齿规则全过，也能以双锯齿规则全过
- **THEN** 该腿胜任 w 位置，不记违规，展示其单锯齿读法

#### Scenario: 推动浪第 3 浪只能读成楔形
- **WHEN** 某推动浪候选的第 3 浪只能以楔形规则全过、不能以推动浪规则全过
- **THEN** 该候选记一次文法违规，违规原因标注「（EWP）」

#### Scenario: 单锯齿 a 引导楔形 + c 终结楔形
- **WHEN** 某单锯齿候选的 a 浪只能读作引导楔形，c 浪只能读作终结楔形
- **THEN** 该候选记一次文法违规

#### Scenario: 各读法都拆不干净（严格口径）
- **WHEN** 推动浪第 3 浪按推动浪、按调整浪都拆不出规则全过的读法，其最佳读法为自身带违规的推动浪
- **THEN** 该推动浪候选仍记一次文法违规（不退回「最佳读法是否匹配」），描述写「拆不出规则全过的读法（最接近：推动浪，自身违规）」，不得写成「实测为推动浪」

#### Scenario: 子腿点数不足
- **WHEN** 双锯齿 w 腿的细枢轴点数少于单锯齿所需的 4 点
- **THEN** 该腿作为叶子（末级 / 不可再分），不计违规

### Requirement: 楔形按位置区分引导楔形与终结楔形
引擎 MUST 把楔形建模为两种独立形态：引导楔形（Leading Diagonal）与终结楔形（Ending Diagonal），各自的标签按实际形态输出，MUST NOT 固定为终结楔形。

- 引导楔形 SHALL 只在推动浪第 1 浪、单锯齿 a 浪位置被接受；其内部 SHALL 接受 5-3-5-3-5 或 3-3-3-3-3 两种结构之一。
- 终结楔形 SHALL 只在推动浪第 5 浪、单锯齿 c 浪、平台形 c 浪位置被接受；其内部 MUST 为 3-3-3-3-3（五条子腿均为调整浪）。
- 楔形 MUST NOT 被接受为推动浪第 3 浪、单锯齿 b 浪或任何调整位置。
- 顶层候选（无父级位置，depth 0 且允许驱动类）SHALL 只保留一条楔形读法：以引导楔形（其内部结构包含终结楔形的 3-3-3-3-3）参与竞争，标签为「推动浪（楔形 Diagonal，位置待定）」，并标 `positionPending`；MUST NOT 以相同点位重复列出终结楔形。
- 两种楔形共享现有楔形价格 / 比率规则（2 浪不破 1 浪起点、3 浪须超 1 浪终点、4 浪须切入 2 浪区间、3 浪不最短等）。

#### Scenario: 锯齿 a 浪位置的楔形
- **WHEN** 某单锯齿候选的 a 腿以楔形规则全过
- **THEN** 该腿标为「推动浪（引导楔形 Leading Diagonal）」，不得标为终结楔形

#### Scenario: 终结楔形出现在锯齿 a 浪
- **WHEN** 某单锯齿候选的 a 腿只能以终结楔形（3-3-3-3-3）成立、不能以推动浪或引导楔形成立
- **THEN** 该候选记一次文法违规

#### Scenario: 终结楔形内部含驱动子浪
- **WHEN** 某终结楔形候选的第 1 子腿只能以驱动浪（五浪）规则全过、不能以调整浪成立
- **THEN** 该终结楔形候选记一次文法违规

#### Scenario: 推动浪第 5 浪为终结楔形
- **WHEN** 某推动浪候选的第 5 浪以终结楔形（3-3-3-3-3）规则全过
- **THEN** 该腿胜任第 5 浪位置，标为「推动浪（终结楔形 Ending Diagonal）」，不记违规

#### Scenario: 顶层楔形不重复
- **WHEN** 顶层区间能以楔形规则全过
- **THEN** 候选池中只有一条 `diagonal-leading` 楔形读法，标签含「位置待定」，没有同点位的 `diagonal-ending`

#### Scenario: JSON 输出区分两种楔形
- **WHEN** 输出树 JSON 中出现楔形节点
- **THEN** 其 `patternId` 为 `diagonal-leading` 或 `diagonal-ending`，不再出现 `diagonal`

## ADDED Requirements

### Requirement: Markdown 报告以 4 条波浪分析简报开头

Markdown 报告 MUST 以标题 `{品种} {周期}波浪分析简报` 开头，紧随固定 4 条编号结论：大局研判、当前浪型、核心生死线（失效点）、关键目标与交易位置（下预警/支撑、上阻力/突破、反弹目标位）。简报后 MUST 有一行免责声明，再附元信息块。原三轴明细 MUST 整体置于 `<details>` 折叠内。简报中的每个数字 MUST 取自既有派生数据，本要求不改变引擎、评分与 `_tree.json`。

#### Scenario: 简报结构完整

- **WHEN** 对存在主选数法与进行中结构的行情渲染报告
- **THEN** 报告首行为 `# {品种} {周期}波浪分析简报`
- **AND** 依次出现以「1. 大局研判」「2. 当前浪型」「3. 核心生死线」「4. 关键目标与交易位置」开头的 4 条
- **AND** 第 3 条的失效点等于 `assessment.invalidation`

#### Scenario: 措辞随主选身份

- **WHEN** 反弹主选身份为 X 连接浪（中继）
- **THEN** 反弹目标位取 XX 投影，并注明到位后警惕 Z 浪
- **AND** 上阻力/突破条注明站稳即转为推动

#### Scenario: 明细折叠

- **WHEN** 报告渲染完成
- **THEN** 轴①②③ 标题均位于 `<details>` 与 `</details>` 之间
- **AND** 报告中不再出现「现状研判（先看这里，TL;DR）」与「大白话版」标题

## MODIFIED Requirements

### Requirement: Markdown 报告按主题轴单一权威呈现

Markdown 报告的明细部分 MUST 按三条主题轴组织，每个主题 MUST 只有一处权威呈现，其余位置至多以一句导读指向权威处、不得重复列出其明细：

- **轴①「大跌走完了什么形态」**：整段历史下跌的形态判定（数法排名）为权威；"整段在更大结构里的角色"（父级候选）MAY 作为其子块出现，但 MUST NOT 重新罗列大跌形态本身。
- **轴②「当前反弹是什么结构」**：当前进行浪竞争结构表（T1-T4 一类的具体子计数枚举）为权威；当前段内部细化、反弹身份研判（连接浪/B/推动）等 MUST 收敛为对该权威表的导读或并入该节，MUST NOT 用另一套字母系统对同一段反弹独立重述一遍。
- **轴③「接下来往哪、何时」**：反弹目标价、失效点、斐波时间窗 MUST 集中于此；时间窗内容 MUST 在整份报告中只出现一次。

结论摘要 MUST 由报告开头的 4 条简报承担；独立的现状研判 TL;DR 与大白话版 MUST NOT 再出现。简报对三轴数字的引用不视为重复明细。

本要求仅约束呈现层；引擎派生、评分与 `_tree.json` 序列化字段 MUST 保持不变。

#### Scenario: 当前反弹只用一套权威标签

- **WHEN** 报告渲染存在当前反弹段（`spanLast → 摆动极值 → now`）的行情
- **THEN** 该反弹的具体子计数只在轴②权威表呈现一次
- **AND** 其它节 MUST NOT 用 `a-b-c`、`XX·B·三浪`、`锯齿` 等另一套标签对同一段反弹独立重述明细，至多出现一句指向轴②的导读

#### Scenario: 转折时间窗全报告仅一次

- **WHEN** 报告包含斐波时间窗内容
- **THEN** 时间窗小节在整份报告中 MUST 恰好出现一次（归属轴③）

#### Scenario: 目标价与失效点集中呈现

- **WHEN** 报告给出反弹目标价与失效点
- **THEN** 明细 MUST 归集于轴③一处
- **AND** 其它节（简报除外）引用同一数字时 MUST 指向轴③、MUST NOT 各自重列一套目标阶梯

#### Scenario: 父级=联合调整时统一层级记法

- **WHEN** 父级候选主选为「联合调整（w-x-y）」且报告展示当前段内部细化
- **THEN** 该内部细化 MUST 以 `w/x/y` 记法呈现（而非 `a-b-c`），并 MUST 显式标注"整段反弹"外层单位与"反弹内部形态"内层单位的级别归属

#### Scenario: 序列化数据零改动

- **WHEN** 对同一输入分别在重构前后运行
- **THEN** `serialize*` 产出的 `_tree.json` 字段 MUST 完全一致

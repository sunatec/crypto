# wave-count-tree

## MODIFIED Requirements

### Requirement: 顶层区间由两框架竞争产生，不钦定全局极值终点
顶层入口 MUST NOT 把顶层区间硬编码为 `[全局高→全局低]`。引擎 SHALL 同台竞争两个顶层框架：框架 A `[全局高→全局低]`（完成框架，末点已确认）与框架 B `[全局高→最新一根K线]`（在建框架，末点为进行中的临时点）。两框架 SHALL 各自递归拆解、各自产出顶层候选，并进入同一个排名池。为防止"已走完大跌 + 之后走势硬塞一个形态、使某腿畸长"，引擎 SHALL 以**腿间比例硬闸门**淘汰畸形数法（而非一刀切裁剪区间）。

#### Scenario: 完成框架与在建框架同台竞争
- **WHEN** 对一段以进行中末端收尾的行情运行引擎
- **THEN** 引擎生成框架 A（截至全局低点）与框架 B（截至最新K线）两套顶层区间，各自拆解并把候选并入同一排名池

#### Scenario: 在建框架表达"当前是更高级别未完成浪的子腿"
- **WHEN** 全局低点之后存在一段反弹、且把"全局低点当作某更大未完成浪的中继"能满足硬规则
- **THEN** 框架 B SHALL 能产出"顶层大浪仍在进行、全局低点为其内部拐点、当前走势为其子腿"的候选，而不再被强制当作"完成结构之后的附加反弹"

#### Scenario: 腿间比例闸门淘汰畸形塞入
- **WHEN** 某候选把已完成的大跌与其后走势塞进一个形态、导致某腿相对同级兄弟浪畸长
- **THEN** 该候选因违反腿间比例硬规则被计一条违规、在排名中被合规数法压到其后

## ADDED Requirements

### Requirement: 排名输出多套完整数法（主选 + 备选）
引擎 SHALL 基于输入时间区间自行判定，输出一组按吻合度排序的**完整数法候选**：最符合者置于最前，其余按分排序。默认 SHALL 输出主选 1 + 备选 3（共 4，候选不足则有几列几）。被硬规则淘汰的候选 SHALL 仍被列出并注明淘汰原因。

#### Scenario: 主选在前、备选按分排序
- **WHEN** 引擎完成一段行情的全框架竞争
- **THEN** 输出一张排名数法表，第 1 行为分最高的主选，其后为按分递减的备选（默认 3 条），淘汰候选附在后并注明原因

#### Scenario: 每条候选给出四要素
- **WHEN** 渲染任一排名候选
- **THEN** 该候选 MUST 给出 ① 现在的浪型（整段形态名）② 已走完的腿（各宏观腿完成状态）③ 当前在哪（进行中末腿 + 其内部当前子腿 a/b/c）④ 评分（违规数 / 越界 / 未完成度）

#### Scenario: 主选展开、备选精简
- **WHEN** 渲染排名数法表
- **THEN** 主选行 SHALL 展开为完整叙述（含内部 a/b/c 逐腿与失效点），备选行 SHALL 逐行精简（形态 / 完成腿 / 当前位 / 评分）

### Requirement: 排名数法融合升级现有结论节并同源写入 JSON
排名数法表 SHALL 取代现有顶部"结论"节（不与其并列以免矛盾）。引擎 SHALL 在 JSON 中输出 `rankedCounts` 数组，每项含 `framing`（A/B）、`pattern`、`legs`（各腿 label/from/to/status）、`current`、`score`、`rank` 与可选 `elimReason`，与 Markdown 排名表同源一致。

#### Scenario: Markdown 与 JSON 表达同一排名
- **WHEN** 引擎写出报告
- **THEN** Markdown 排名表与 JSON `rankedCounts` 表达同一组候选、同一排序、同一评分

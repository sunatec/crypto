# 提案：多套数法排名输出 + 解开顶层区间焊死

## Why

现有 `analyze-wave-tree.js` 只给用户**一套**顶层主选数法，且这套主选被两处限制"钦定"、而非"竞争派生"：

1. **分段搜索不完整——第一名可能就是错的。** `segmentations()`（[analyze-wave-tree.js:885](analyze-wave-tree.js:885)）对每种形态**只回一个贪心坍缩结果**（`coarsenByPairs` 反复删相邻最小振幅对，只保护全局最高/最低）。`decompose` 每形态也就只打分这一种。实证：用户手数的双锯齿 `126296→80524→97963→57718`（越界 0.005）按引擎**自己的 comparator** 优于引擎主选的三锯齿（越界 0.017），但引擎**从未生成它**——它贪心保留的是 `126296→60001→82814→57718`（越界 0.127，更差）。**最优分法从没进过打分池。**

2. **`directionalTopSpan` 把全局低点焊死成"终点"。** 它强行把顶层区间截成 `[全局高→全局低]`（`126296→57718`），低点之后的走势一律当"附加的在建反弹"另处理。后果：**"当前低点只是更高级别未完成浪的中继、后面还有下跌"这类完全合规的数法（探索中的"读法2"）结构上无法表达。** 实证：把 `Y=97963→now` 当一个还在走的双锯齿（`w′=97963→57718 / x′=57718→66924 / y′=66924→新低`）逐块查规则，每块违规都是 1 条、和整段其它数法同水平——它没被证伪，只是引擎产不出来。

3. **用户要"你自己判定 + 按吻合排序输出多套"。** 当前只输出单选，不给"最符合的在前、其余按分排序"的候选集。

## What Changes

对 `analyze-wave-tree.js` 三处改动（`analyze-kline-wave.js`、`analyze-wave-manual.js` 零改动）：

1. **补全分段搜索（修缺陷 1）**：`segmentations()` 从"单一贪心坍缩"换成"**显著性短名单 + 子序列穷举 + 打分取 top-K**"——先按摆动显著性取最显著的前 M 个内部枢轴（M≤12，恒含全局高/低），在其上穷举所有合法交替 H/L 的 n 点子序列，逐个交由现有 `scoreCandidate` 打分，回最优 K 套喂入候选池。下游打分/排名/beam 原样复用。

2. **解开 `directionalTopSpan` 焊死（修缺陷 2）**：顶层区间不再钦定 `[全局高→全局低]`，而是**同台竞争两个框架**——框架 A `[全局高→全局低]`（完成）对框架 B `[全局高→now]`（在建）。框架 B 是半成品，只查"到目前为止该满足的硬规则" + **未完成度惩罚**，与框架 A 同一把尺排名。原焊死为防"第 1 浪畸长"，改由**腿间比例硬闸门**淘汰畸形数法来替代（不回退到一刀切裁区间）。

3. **排名数法输出（满足需求 3）**：把现有顶部"结论"节升级为一张**排名数法表**——**主选 1 + 备选 3（共 4）**，各条给：① 现在的浪型（整段形态）② 已走完的腿 ③ 当前在哪 ④ 评分（违规数/越界）。主选展开成完整叙述，备选逐行；被硬规则淘汰者仍列出并注明原因。JSON 同步产出排名候选数组。

## Impact

- 改动文件：`analyze-wave-tree.js`（`segmentations`/`coarsenByPairs` 重写、新增显著性排序、顶层区间竞争、在建框架打分、排名渲染 + JSON）。
- 涉及能力：`wave-count-tree`（顶层区间竞争、排名输出）、`wave-fit-scoring`（分段搜索完整性、在建框架打分、腿间比例闸门）。
- 不改：数据源、CLI 参数、`analyze-kline-wave.js`、`analyze-wave-manual.js`。
- 兼容：现有单套主选输出被排名表的"主选"行取代，语义向后兼容（主选仍是分最高者）。

## 非目标

- **不新增形态**：形态集仍冻结为现有清单。
- **不做更全的区间候选（Q5=a 起步）**：顶层区间只竞争 `[hi→lo]` 与 `[hi→now]` 两框架；`[hi→每个显著低点]` 的更全枚举留作后续增量。
- **不做无限嵌套**：在建框架的高级别嵌套深度沿用现有 `maxDepth`，不为"读法2"专门放开深层多重嵌套。
- **不引入书外指标**：判定仍只用书内可计算知识。

# 设计：多套数法排名 + 解开顶层焊死

> 本设计经一次 grilling 会话逐节确认。决策：Q1=(c)（补搜索 + 解开焊死）、Q5=(a)（两框架竞争）、Q6=(a)（同尺 + 未完成度惩罚）、Q7=(a)（规则淘汰畸形）、Q2/3/4（排名表：四要素 / 主选1+备选3 / 融合升级结论节）。
> 前置探索证据见本 change 的 proposal「Why」。参考理论：《波浪理论详解》。硬约束：仅改 `analyze-wave-tree.js`。

## 1. 问题定位（两处"钦定"而非"竞争"）

```
用户诉求：基于输入区间，引擎自己判定 → 排名输出多套「现在的浪型 / 已走完哪些腿 / 当前在哪 / 评分」

阻碍A（搜索不全）：segmentations() 每形态只回一个贪心坍缩 → 最优分法从没被打分
阻碍B（区间焊死）：directionalTopSpan 钦定 [全局高→全局低] → 在建高级别数法无法表达
```

两者叠加使"排名"不可信：即便把现有候选排序，第一名仍是被漏搜/被焊死扭曲的结果。

## 2. 补全分段搜索（Q1 的 b 部分）

### 2.1 现状（根因）

```js
function segmentations(segFine, n) {
  if (segFine.length === n) return [segFine.slice()];
  const coarse = coarsenByPairs(segFine, n); // 贪心：反复删相邻最小振幅对，仅护全局高/低
  return coarse ? [coarse] : [];             // ← 每形态只回「一个」
}
```
搜索空间/形态 = 1。`coarsenByPairs` 不保护 `80524`（第一大低）与 `97963`（第一大高），可在坍缩中把它俩当噪音删掉。

### 2.2 目标算法：显著性短名单 + 子序列穷举 + top-K

```
① 显著性排序：给内部细枢轴按「拓扑存活序」打分（实现时对原设计的修正，见下）
     取最显著的前 M 个（M≤12），恒并入全局高、全局低、区间首尾。
② 子序列穷举：在 {首 + 短名单 + 尾} 内，枚举所有「交替 H/L、恰 n 点、首尾固定」的子序列
     M≤12、n=4~6 → 数百组合，毫秒级；短名单是防组合爆炸的闸门。
③ 打分取 top-K：对每套跑现有 scoreCandidate（含文法子拆解），回最优 K 套。
```

**显著性度量：实现时从「邻居落差」修正为「拓扑存活序」。** 原设计草案的 `prominence(pivot) ≈ min(左右邻居落差)` 是纯局部量度，实测会漏判 `97963`、`82814` 这类全局关键拐点——若其紧邻的细枢轴恰好很近，min(左右落差) 会很小，被排到短名单之外，让位给无关紧要的小反弹（如某个仅比邻居高一点点的次要波动）挤进短名单，产出不合理的宏观切分。改为 `significanceRank`：复用 `coarsenByPairs` 同一套「反复删相邻振幅最小对」的贪心坍缩，但不停在目标点数 n，一路做到只剩首尾，记录每个内部枢轴被删除的次序——存活越久（越晚被删）代表在全局拓扑上越显著。这是一次性预计算（O(n²)，n≤82 时可忽略），比纯局部量度更稳健。

**为什么修好目标 case**：`80524`、`97963` 是本段拓扑意义上最持久的两个摆动，显著性必进短名单。但搜索补全后实测找到的还不止用户手数的双锯齿——发现了一个**零违规**的单锯齿 `126296→84400→97964→57718`（此前穷举全部 12 种顶层数法，零违规候选数=0）。`84400` 不是最深的低点（`80524` 更低），但作为 wave-1 的终点更贴合"第 5 浪失败/截断"的合法 Elliott 结构，比人工只盯着"最深低点"更准。已用独立的 `evaluateExplicitCount` 路径交叉核对，非 bug。

**契约不变**：`decompose` 已是 `for (const pts of segmentations(...)) { 打分 }`，`segmentations` 多回几套即可，下游打分/排名不动——但下游"何时展开子树"需要改，见 §2.4。

### 2.4 配套修复：两段式 beam（避免分支因子随深度指数放大）

`segmentations()` 从每形态回 1 套变为最多回 `SEG_MAX_COMBOS=60` 套后，`decompose()` 原先的「对每个原始候选都先递归展开完整子树（含 `legCharacter` 对每条子腿的双向 `decompose`），再统一排序截断到 `beamK`」会让分支因子随深度指数级放大——生产默认参数（`beamK:3, maxDepth:5`）下实测 **OOM 崩溃**（`beamK:99` 探索性测试）及 **38126ms**（生产默认参数）。

修复为两段式 beam：
1. **前沿筛选（便宜）**：先只算 `scoreCandidate` 返回的基础分（`tier1/tier2/complexity/tier3`，不含 grammar 与 tier4，本就不需要子树），按此粗排，只取前 `preRankKeep = max(beamK×4, 12)` 名。grammar 违规只会把 tier1 往上加、不会减，缓冲区留够余量以降低"基础分领先者被 grammar 反超"时漏选真实最优的概率。
2. **子树展开（贵，只对幸存者做）**：只对前沿筛选后的候选才递归 `legCharacter`/子树/`crossDegreeHits`，计算最终完整分。
3. **记忆化缓存**：`decompose` 加按 `区间起止索引|允许角色|深度` 为键的缓存（挂在 `opts.cache`，per-run 一个 `Map`）。不同顶层候选常共享同一段子腿区间（如两种分段都会切出同一段"97963→60001"），缓存消除这类重复递归。

两者叠加：38126ms → 348ms（约 100 倍）。若仅两段式 beam、无缓存，仍需数秒级；缓存是让"多套分段"在深递归下保持轻量的关键。

### 2.3 边界与回退

- `segFine.length === n`：直接返回该唯一切分（不变）。
- 短名单不足 n：退回全体细枢轴上的受限穷举或旧贪心（避免空结果）。
- 复杂度护栏：M 与 K 设上限；超大区间下 n=6 的子序列数用 M 约束在千级内。

## 3. 解开顶层区间焊死（Q1 的 c 部分 + Q5=a + Q7=a）

### 3.1 两框架竞争（Q5=a）

```
框架A（完成）：topSpan = [全局高 → 全局低]        （现状；末点已确认）
框架B（在建）：topSpan = [全局高 → now]           （末点=进行中的临时点）
两者各自跑 decompose，产出各自的顶层候选，统一进排名池。
```

`buildCountTree` 入口从"钦定 A"改为"生成 A、B 两套 topSpan → 分别拆解 → 合并候选排名"。A 表达"读法1（57718=底）"，B 表达"读法2（57718=中继，当前是子腿）"。

### 3.2 在建框架的半成品打分（Q6=a）

框架 B 的顶层形态未走完，`scoreCandidate` 需支持"进行中评估"：

| 维度 | 处理 |
|---|---|
| 已走完的腿 | 照常跑硬规则闸门与越界 |
| 进行中的末腿 | 只查"到目前为止不可能违反的规则"（如不重叠、比例下界），未定项**不判违规也不判通过** |
| 未完成度 | 新增 `incompletenessPenalty`：按"还差几腿才成形 / 末腿完成度"给一个惩罚，计入排序键 |

**同一把尺（Q6=a）**：框架 A、B 用同一分层字典序排序；**未完成度惩罚**确保半成品不因"还没机会违规"而虚高，压过合规的完整数法。惩罚落在 tier2 之后、tier3 之前的新层，或并入 tier2 的加权项（实现时择一，见 tasks）。

### 3.3 防"第 1 浪过长"的规则闸门（Q7=a）

原 `directionalTopSpan` 一刀切裁区间，是为防"大跌+反弹硬塞一形态、第 1 浪畸长"。解开后改用**硬闸门**保留该好处：

```
新硬规则（leg-proportion gate）：同级兄弟浪中，任一浪的幅度/时间不得畸长于其它浪
  → 违反即淘汰（tier1 计一条），把"畸形塞入"的数法自然排除，而非靠裁区间。
```

这样既解开焊死、又不回退。

## 4. 排名输出（Q2/Q3/Q4）

### 4.1 候选池与排序

```
候选池 = 框架A顶层候选 ∪ 框架B顶层候选（各含 top-K 分段）
排序   = 现有分层字典序（tier1 违规数 → tier2 越界 → 未完成度 → tier3 指引 → tier4 跨级别）
输出   = 主选1（分最高）+ 备选 N（见下：Q3 复议）
```

**Q3 复议：从"主选1+备选3"改为"按形态去重 + 全列（上限 8）"。** 上线后发现只列 3 条太少——
真实行情里顶层常有 10+ 条零违规候选。但直接放大数量会堆一片近似重复（如同一"双重横向整理"
只差内部连接点的 5 条变体）。故改为**按 (框架 + patternId) 去重**、每族只留分最高的一条代表，
再把所有不同读法按分排序全列，`RANKED_MAX=8` 封顶。这样"列几条"由"实际有几种本质不同的
合规读法"决定，而非钉死数量。BTC 1d 实测输出 8 条：4 种零违规族（单锯齿/推动/双重横向/三重
横向）+ 2 条 ×1 近失（平台/规则平台）+ 2 条 ×2（双锯齿/三锯齿），×5 三角形等劣解被分数自然
挤出，不会出现在表里。

**配套的搜索侧改动（关键）**：要"按形态全列"，前提是每种形态族的**干净代表**都被找到。两处：
1. `decompose` 顶层（depth 0）**不做 preRankKeep 截断、全量展开所有候选切分**——因为 base
   score 预筛含 complexity，complexity-1 变体一多就会把 complexity-2/3 的形态族在展开前挤掉；
   且某族是否干净常取决于展开子树后的文法违规（base score 看不出），必须多分点全量打分。
   顶层只有一个节点、子腿分解经 `opts.cache` 大量共享，实测 378 候选全展开后总耗时仍在 ~3s
   （含网络）。深层不变，仍按 preRankKeep 收敛。
2. `decompose` 顶层保留**全部** alternates（`ranked.slice(1)`）供排名表去重全列；序列化时另用
   `dedupeAlternatesForSerialize`（按 patternId 去重、上限 8）控制 JSON 体积（实测 ~74KB）。

### 4.2 每条候选四要素（Q2）

| 要素 | 来源 |
|---|---|
| ① 现在的浪型 | 顶层形态名（如"双锯齿 w-x-y" / "在建：Y 未完成的双锯齿"） |
| ② 已走完的腿 | 顶层各宏观腿的完成状态（w/x 已完成、y 进行中） |
| ③ 当前在哪 | 进行中末腿 + 其内部当前子腿（复用现有 `deriveCurrentInternal` 的 a/b/c 逐腿） |
| ④ 评分 | 违规数 / 越界 / 未完成度 |

### 4.3 渲染与 JSON（Q4=a 融合升级 → 实现时修正为并存）

- Markdown：**实现时发现与原计划的偏差**——"排名数法表"（回答"大跌本身最像哪种数法"）与既有"# 结论：..."节（`deriveParentDegree`，回答"大跌+反弹在组成什么更大结构"，属上一 session 已实现并验证的独立功能）是**不同的轴**，并非同一件事的两种呈现，谈不上"融合升级"。故改为**新增独立顶层节**"# 数法排名"，置于"结论"节之上，两节并存：主选行展开（腿逐条 + 评分 + 指向进行中结构）；备选表格精简（形态 / 方向 / 腿 / 评分）。淘汰行（tier1>0 的候选）目前仍随排名列出而非单独标注"淘汰原因"——框架A的备选没有"淘汰"概念（都是同一 topSpan 的不同切分尝试，只是分数更低），"淘汰+原因"的语义留给阶段三框架B（结构性质冲突等硬闸门）更贴切。
- JSON：新增 `rankedCounts: [{ rank, label, direction, legs:[{name,from,to,status}], score:{tier1,tier2,complexity,penalized} }]`，与 Markdown 同源。阶段三接入框架B后再补 `framing`/`elimReason`/`incompleteness` 字段。

## 5. 影响面与风险

- **改动集中在 `segmentations`/`coarsenByPairs`（重写）、新增显著性排序、`buildCountTree`（两框架）、`scoreCandidate`（在建打分 + 腿间比例闸门）、渲染层**。
- **风险 1（性能）**：子序列穷举与双框架使打分量上升；用 M、K 上限 + 显著性短名单约束。
- **风险 2（在建打分公平性）**：未完成度惩罚的标定需回归金标准，避免框架 B 系统性过高或过低——列为验证任务。
- **风险 3（回归）**：解开焊死可能改变既有单套输出；以现有金标准报告做前后对照，主选语义须保持"分最高者"。

## 6. 分步落地建议

1. 先做 §2 分段搜索补全（局部、收益即时：目标 case 立刻被顶到第一）。
2. 再做 §4 排名输出（此时框架 A 内部已可信）。
3. 最后做 §3 解开焊死 + 在建打分（架构级，单独验证未完成度标定）。

§1–§2 可独立交付；§3 是真架构改动，建议在其后单独一轮验证。

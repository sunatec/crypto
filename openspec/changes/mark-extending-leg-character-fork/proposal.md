# 提案：进行中末腿"两可"时，标出被角色压掉的另一性格读法（5浪/3波分叉）

## Why

`gate-extending-final-leg-rules` 修好了"延伸中末腿不该被会翻转的规则判违规"，但明确把「进行中末腿的内部性格/形态如何标」列为非目标。这个口子在 BTC 备选1（框架B 双锯齿，y=97964→57718⏳延伸中）上暴露：

其**末端仍在成形**的那条腿 `82814→57718` 报告显示成 **单锯齿（3波调整）**。但实测该腿是**歧义腿**（`canDrive && canCorrect`），两种读法都零违规、且它的**首选性格恰是驱动（5浪）**：

```
legCharacter(82814→57718):
  drivingNode:    推动浪(5浪)  tier1=0   ← 因该腿占双锯齿的 y 位(要求调整)，算完即丢弃
  correctiveNode: 单锯齿(3波)  tier1=0   ← 采用、显示
```

问题：这条腿被塞进双锯齿的 **y 角色**（文法要求 w/y 为调整），于是引擎在其两个合规读法里**选了调整那个、丢掉了驱动(5浪)那个**——树里根本不留。用户只看到"单锯齿"，看不到"它其实也可以是5浪"。

而这在**还没走完的末端腿**上尤其误导：它是否是 5浪，**决定整棵计数树是维持双锯齿、还是换成推动族**。把一个成形中的两可结构显示成板上钉钉的"单锯齿"，隐藏了这个真实的、量级最大的分叉。

> 注：这里**没有硬规则被违反**（歧义腿放任何角色都不违规），所以 `gate-extending-final-leg-rules` 的规则闸门不适用——这是"选择性显示"问题，不是"误判违规"问题。

## What Changes

对 `analyze-wave-tree.js`（仅显示/标注层，`analyze-kline-wave.js`、`analyze-wave-manual.js` 零改动）：

1. **保留被角色压掉的跨性格代表**：对**进行中末腿链上仍在成形、且两可（canDrive && canCorrect、两读法均 tier1=0）**的腿，`legCharacter` 除采用角色所需性格外，**额外留一份"另一性格的最优合规代表"**（当前被算完即丢）。仅这一条腿、仅留一个对侧代表（不留同性格的近似形态）。

2. **报告标注"性格分叉"**：在该腿处标注「⏳此段两可：也可读作 **5浪（推动）** / **3波（锯齿）**；改此性格则顶层换族（如推动浪族）」。只标**跨性格分叉**（粒度2），不罗列所有 tier1=0 形态（粒度1 噪音），不改被选中的计数与排名。

## Impact

- 改动文件：`analyze-wave-tree.js`（`legCharacter` 保留对侧性格代表、进行中末腿链定位、报告标注渲染、JSON 透传）。
- 涉及能力：`wave-count-tree`（进行中末腿的两可标注）。
- 产出变化：报告在进行中末腿处新增一行"两可"提示；`_tree.json` 对应节点新增 `altCharacter` 字段。选中的计数、排名、违规/待判均不变。
- 不改：数据源、CLI、规则集、排名去重、`gate-extending-final-leg-rules` 的规则闸门与终点锚定。

## 非目标

- **不罗列所有合规形态**（粒度1）——同性格近似形态仍按现有去重压掉，只标跨性格分叉。
- **不改选中的计数与排名**——纯标注，不因"另一性格也合规"改变主选/备选顺序。
- **不重构进行中结构的下钻深度**（粒度3 / "内部未定"整体策略）——另议。
- **不碰规则闸门**（`gate-extending-final-leg-rules` 已处理量化规则）。
- **不引入书外指标。**

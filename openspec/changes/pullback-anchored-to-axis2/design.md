# Design

## Context

动机见 proposal.md。实现相关的现状：

- `buildCountTree` 在建树时调用 `buildCurrentWaveStructures`（轴②），之后主流程才调用异步的 `enrichCurrentPullback`（回撤叙述，可能下钻子级别）。因此回撤叙述生成时轴②已就绪，可以直接读；反过来让回撤证据影响轴②排名则有时序问题（本次不做）。
- `buildCurrentWaveStructures` 各模板先写 `soft`（性格契合），随后的证据循环用 `tpl.soft = 已验证腿数` 整体覆盖。
- `renderPullbackNarrative(nr, precision, bounceHyp)` 一次产出整段「当前高点回撤研判」，由 `renderAxis3` 挂在轴③；`enrichCurrentPullback` 也用它生成 `narrative.text`。去向句来自 `pullbackAfterUpgrade(level, bounceHyp, n)`。
- `ips.pullback.fibTargets` 已有上冲段的 0.382 / 0.5 / 0.618 回撤位；`zwaveProjection` 已有 (z) 档位。
- 摆动极值取的是 `post` 段最高（最低）枢轴，所以"反弹越过摆动极值"的状态在主级别数据里不会被叙述看到——一旦越过，极值就换了。越过摆动极值只会以条件句的形式出现在文字里。

## Goals / Non-Goals

**Goals:**
- 轴②排名能反映上冲段的性格，与轴③主选同源。
- 回撤结构细化只在轴②出现一次，浪名分级清楚，身份、约束和去向都取自轴②。
- 既有 JSON 字段不变，只做新增。

**Non-Goals:**
- 回撤内部证据（三波 / 五浪、升级线）回流参与轴②打分。
- 合并「上表内部细化导读」（父级口径那一句）。
- 改 T4 选点、改 `bounceHyp` 本身、改轴③反弹目标小节。

## Decisions

### D1 软分 = 已验证腿数 + charFit
模板里原来的 `soft` 改名为 `charFit` 并保留；证据循环结束后 `soft = verifiedCount + charFit`，`softReasons = ['已验证腿 n 条', '上冲段五浪/三波，契合/不契合①（或 a）的要求']`。
- 备选：只用 `charFit` 作次级排序键（tier1 → verified → charFit）。没选它，因为这样性格信号仍然排在已验证腿数后面；而已验证腿数在各模板间口径不一（T4 有 5 条腿可验证，T2/T3 只有 1 条），相加更公平。
- 与 `engine-backed-current-impulse-template` 的关系：那个变更计划删掉 T4 的 `leg1Char` 信号，正好对应把 T4 的 `charFit` 置 0，合成方式不冲突。

### D2 身份对照只认"⏳ 腿从摆动极值起步"的存活情景
`buildAxis2Roles(cws, ctx)` 遍历 `cws.structures`，筛选条件：`tier1 === 0`，且存在 `status === '⏳进行中'` 的腿、其 `from === cws.ext`。按模板 id 映射角色：
- `connector-bx` → `zigzag-b`
- `reverse-impulse-2` → `impulse-2`
- `cont-impulse-3` → `impulse-3`

T4（⏳ 腿是 ④→摆动极值的 ⑤，回撤只是"⑤内部或⑤后"）不进入身份对照；它若存活，就在身份块末尾加一句备注。
- 备选：按 `tendency` 映射。没选它，因为倾向相同的模板身份不同（T3 和 T4 都是"看多"）。

### D3 约束表写成数据、带书页码
每个角色一份常量：`priceLimit`（价位 + 是否允许触及）、`timeMax`（倍数）、`timeTypical`（倍数区间或 null）、`formsCommon` / `formsExcluded`、`aRatioTypical`（仅 `impulse-2`）、`refs`（书页码）。时间用 K 线根数（与 `waveFourTimeGate` 同口径）计算：参照腿根数 = 摆动极值的 index − 起点 index；已走根数 = 最后一根 K 线的 index − 摆动极值的 index；常见时间窗按"摆动极值时间 + 倍数 × 参照根数 × 平均根距"换算成日期，平均根距取整段 K 线（首尾时间差 ÷ 根数），以免股票跨周末 / 假日时被最后一对间距放大。

形态相容性只比对两类：
- `formsExcluded` 是否出现在整体读法里（如 `impulse-2` 遇到收缩三角形）；
- 首选内部形态是否属于 `formsCommon`。

两者都只输出文字，不计违规（规格要求）。

### D4 记号分三级
- 轴②表的腿名不变。
- 进行中腿内部用括号记号：整体读法 (a)(b)(c) / (w)(x)(y)；三重联合形读法 (w)(x)(y)(xx)(z)。两种读法是同一级别的竞争读法，各自带小标题"读法一 / 读法二"，避免同名 (w) 被混读。
- (a) 内部只写"形态名：价链"。

只改渲染层；JSON 里 `combinationReading.legs` 的键（W/X/Y）保持不变，以兼容既有字段。

### D5 渲染拆两半，保留拼接函数
- `renderPullbackLegDetail(nr, precision)`：返回「## 进行腿细化（⏳ 腿内部）」，包括身份对照、级别、内部形态、结构线、读法一（整体）、读法二（三重联合形）、两条 70% 线。由 `renderMarkdownReport` 在轴②表之后、「上表内部细化导读」之前插入。
- `renderPullbackTargets(nr, precision)`：返回「## 回撤目标位（⏳ 腿）」，包括 `retraceLevels`（含共振标记）、(z) 两条路、平台形 (c) 目标（状态②）和去向。由 `renderAxis3` 挂在原位置。
- `renderPullbackNarrative` 保留，签名去掉 `bounceHyp`，返回两者拼接，供 `narrative.text` 和既有单测使用。
- 备选：直接删除 `renderPullbackNarrative`。没选它，因为测试和 `narrative.text` 依赖面大，保留拼接函数可以分批迁移。

### D6 去向句改读 `axis2Roles`
`pullbackAfterUpgrade(level, roles, n)`：
- 有存活身份时：`basis: 'axis2'`，文字为"前段上涨视为已走完（转势 / 中继两情景的前提）；本回撤走完后：#1 {label} → {下一腿} {投影}；#2 …"。
- 无存活身份时：`basis: 'generic'`，文字为"轴②暂无存活情景，去向待定"。

结局文字由纯函数 `pullbackAftermath(nr, n)` 生成；`afterUpgrade` 与 `zwaveTargets.*.aftermath` 只由数据层 `finalizePullbackAftermath` 写入（`enrichCurrentPullback` 里调用，轴②身份变化后须重新调用），渲染函数只读，不再在渲染时改写 JSON（审查修复：避免 `narrative.text` 与 JSON 不一致）。

升级线一句改为证据措辞：已跌破升级线时，补"削弱 ⑤ 情景的 ⑤ 内部回撤分支"（仅在 T4 存在时写）。

### D7 共振判定
`retraceLevels = pb.fibTargets.map(t => ({ ...t, confluence: zTargets.filter(z => |z.price − t.price| ≤ 0.01 × t.price) }))`。比对对象取 (z) 跌破路径的主带上下沿、延伸档和极端档。容差 1% 是固定常数；BTC 当前 0.382 位 76090.2 与主带 75356.43–76201.02 重合。

### D8 越过摆动极值的措辞
分级失效线一段改为：越过摆动高点时，轴②以新高为摆动极值重新研判；扩散 / 顺势平台 (b) 可越过 (a) 起点只作备注；联合形和平台形上限作为备注线位保留，删去"高一级读法整体作废"这种独立分支的表述，统一改为"整体读法作废"。

### D9 读法三（⏳ 腿已在回撤真低点走完）
旧规格把整段内部的 a-b-c 一律称为"(a)/(w) 内部结构"，等于默认 ⏳ 腿没走完；但轴②下一腿投影本就从回撤真低点起量，"已走完"是轴②表隐含的读法，叙述里却没有。补为与读法一、读法二并列的读法三：
- 数据：`buildCompletedReading({ hd, patterns, roles })`，只在读法一存在且 `state !== 'broken'` 时给出（跌破 (a) 终点后真低点已换）；内部形态取非三角形读法。
- 否定线 = 真低点；与读法一的区分只用书中可判的条件：下一腿须五浪、(b)/(x) 须三波；越过摆动极值只写"支持"，因扩散 / 顺势平台 (b) 也可越过。
- 浪②的 (a) 有两种口径：读法一的单锯齿分支以整段为 (a)（身份对照表，现标"读法一"），读法三以单锯齿首段为 (a)（读法三段落）。
- 排在读法二与两条 70% 线之后，不改读法一 / 读法二的编号，避免既有引用错位。
- 备选：把读法三排第一并重编号。没选，因为编号变动会让读法一 / 二的交叉引用（失效线、两条 70% 线、轴③ (z) 两条路）全部改写。

### D10 内部端点不是跨度极值时只注明、不改终点
引擎的端点规则已收窄为 `legsRespectOrigin`，允许 §3.15 失败第五浪 / §4.7 截断的正统终点不在跨度极值上。BTC 单锯齿首段读作引导楔形 87395.67→82563→84352→79800→82940.81→80684.36（第 5 浪未破 79800），若强取 79800，首段只能读成终结楔形，违反"单锯齿 a 须为推动浪或引导楔形"。因此不改终点，只在价链后注明更极端价及原因（`beyondEnds`）。
（D13 之后 BTC 单锯齿首段可直接止于 79800，本例不再出现注释；机制保留给其它失败第五浪 / 截断。）

### D11 末段延伸读法：跌破真低点只否定"在此走完"
读法三原先写"跌破真低点即否定（回到读法一 / 读法二）"，漏掉了"同一形态末段继续走"：单锯齿的 (c)、平台形的 (c)、双重横向的 (y) 都可以越过真低点，真低点之后的小反弹只是末段内部的反弹。改为：
- 否定句只否定"在此走完"，并指向末段延伸读法。
- 数据 `buildExtensionReading(patterns, candles, { zt, fibTargets, trigger, state })`，倍数常量 `EXTENSION_RULES` 逐项注明对应的引擎规则 / 指引 id：单锯齿 c-common-ratio / c-not-far-beyond-1.618a / c-between-0.9b-and-5b / c-lt-10a-and-10b；平台形 c-common-ratio（1.818 = 1.618 + 引擎容差 0.2）/ c-gross-limit / c-lt-10a-and-10b；双重横向 y-le-5w。平台形 (c) 上限按运行总量，换成价格只能用净幅度，故标"最晚"。
- 时间上限按根数（同 `legIndexTime`），日期 = (b)/(x) 终点时间 + 上限根数 × 整段平均根距；需要拐点的 `index`，故 `rankedPatterns[].points` 补 `index`。
- 共振沿用 1% 容差，比对对象在回撤位共振的 (z) 主带 / 延伸 / 极端之外，加入 (z) 破位档和上冲段回撤位（`zLevelsOf` / `confluenceAt` 从 `retraceLevelsWithConfluence` 抽出复用，回撤位自身的共振口径不变）。
- 已跌破 (a)/(w) 终点（状态③）时保留，与读法一的 (c)/(y) 并列；位置：结构说明在轴②，数值在轴③（"轴③只留目标位"）。
- 备选：只在跌破后才出现。没选，因为跌破前读者最需要知道"跌破后去哪、到哪不成立"。

### D12 双锯齿单独成族
`analyzePullbackCompleted` 按 `manual.patternType` 去重，单锯齿与双锯齿同为 `zigzag`，双锯齿被单锯齿挡掉。BTC 已走完段有一条零违规、端点均为跨度极值的双锯齿 87395.67→79800→84898→79220.74——它是唯一以真低点 79800 为分段点的合规读法（以 79800 为单锯齿 (a) 终点时，(a) 只能读成扩散终结楔形，违反文法）。
- 双锯齿另成一族，插在单锯齿之后；三锯齿仍留在锯齿族（不在本次范围）。
- 族内挑选：端点为跨度极值且拐点链不与已列形态重复 → 端点为跨度极值 → 引擎首选。引擎在双锯齿族里排第一的是 87395.67→82563→87220→79220.74，与平台形同链，只换名字不提供新分段，故跳过。单锯齿不套用此挑选（取引擎首选；D13 之后 BTC 单锯齿首选即 79800 分段）。
- 形态清单截取上限 3 → 4，免得双重横向整理被挤出。
- 末段延伸新增 `zigzag-double` 规则：y-near-w-or-1.618（1 / 1.618，容差上沿 1.818 为指引线）、y-gt-0.9w（常见下沿）、y-lt-5w（失效价）、y-lt-5w 时间。未纳入 y-not-both-5x（价格与时间同时超 5×(x) 才违规，是联合条件）与 y-inside-0x（通道线，不是价格下限）。失效价越过轴②底线时注明以底线为准。

### D13 楔形"3 浪短于 1 浪"降为指引
引擎原把"楔形须收敛：3 浪短于 1 浪、5 浪短于 3 浪"（`diagonal.ratio.converging`）定为硬规则。核对书第 1~7 章：§1.5 驱动浪通用规则、楔形 4 浪须切入 2 浪价区、§2.3 楔形适用收缩通道、§4.6 扩散终结楔形只在 5 浪 / c 浪，均无长度递减的原文（楔形专章不在整理版中）；它来自 Frost & Prechter 对收缩楔形的描述。
- 边界收敛 `diagonal.pattern.boundaries-converge` 仍为硬规则（有 §2.3 依据）；长度递减改为指引（命中加分、不命中不扣违规）。
- 扩散终结楔形原本就去掉这两条，现改为从指引中去掉长度递减。
- BTC 87395.67→79800：1 浪 4832.67、3 浪 6826.44、5 浪 4552，边界收敛，原先只因长度规则落选；现为合规引导楔形，单锯齿 87395.67→79800→84898→79220.74 零违规，(a) 不再取 80684.36。
- 连带：双锯齿族内挑选的"不与已列形态同链"只排除别族（平台形 / 联合形）；与单锯齿同链合并列出并注明差在首段内部，否则双锯齿会退回与平台形同链的 87395.67→82563→87220→79220.74。
- 影响面：全量测试（含 golden）只有 BTC 回撤这组断言随 (a) 终点变化，其它计数未变。旧引擎 `analyze-wave-manual.js` 的同名规则未改（报告不经它判形态）。

### D14 细枢轴：外包线两侧、同型合并补桥点、去颠倒段、归位
`detectPivots`（lookback 1）原有三处会漏掉真实摆动：外包线只按"哪侧更突出"留一侧；相邻同型只留更极端者，其间的反向摆动一并丢掉；逐级推进中两侧各只比相邻 K 线极端的点会连成方向颠倒的段。实测 BTCUSDT 日线有 16 处相邻枢轴之间存在更极端价（如 04-29 的 74937.52、09-11 的 76046.58、07-06 的 64700），1 处颠倒（11-14 L94012.45 → 11-20 H93160）。
- 外包线两侧都出枢轴，同一根 K 线下标相同；日内先后按开收盘估计（阴线先高后低），有小周期时仍以小周期复核为准。下游时间口径已有 `legIndexTime` ≥ 1 根兜底。
- 同型相邻先补桥点再合并：保留 B 时桥点落在「前一枢轴 → B」段，保留 A 时落在「A → 后一枢轴」段；桥点越过该段另一端才保留三点。只在前一段比较会把逐级推进中的小反弹也当成摆动（试过：BTC 日线枢轴 120 → 212）。
- 颠倒段成对去掉；最后把每个中间枢轴挪到与前后枢轴之间最极端的 K 线（如 04-22 阳线先探出的低点挤掉 04-23 的 76960）。
- 结果：五份夹具三类异常全为 0，BTCUSDT 日线枢轴 120 → 132；87395.67 之后的回撤枢轴不变。
- 连带：上冲段浪(1) 57800.19→66956.15 在日线上多出 64700 / 61544.56 两个真实枢轴，拆出的第 3 浪终点 64692.83 比第 1 浪终点 64700 低 7.17，日线判不成五浪；真实报告经 4h 复核仍为引导楔形。原先日线能过，是因为漏掉这两个枢轴后只剩 4 点、按"待验证"放过。单测改走与报告相同的复核路径（夹具只含浪(1) 22 天的小时线，约 4 秒）。金标 W-X-Y 的 w 腿、W 子角色测试的 c 腿原先依赖颠倒段 / 漏掉的 104550、99170，改用修正后的事实。
- 未改：旧引擎 `analyze-kline-wave.js` 自带的同名函数；`wave-subwave-verification.js` 的 `dropFilledPivots`（去掉补齐 K 线上的枢轴后同型合并，不补桥点）。

## Risks / Trade-offs

- [BTC 轴②第 1 名翻转，简报、导读、golden 中取首行的断言随之变化] → 实施时先只做 D1、跑全量测试，逐条核对变化是否都源自排名翻转，再进入第二步。
- [`leg1Char`（轴②，maxDepth 3）与 `ips.swingChar`（maxDepth 2）可能不一致，导致轴②排名与轴③主选仍然相反] → 本次不统一两者；进行腿细化的身份对照按轴②顺序列出，并在两者不一致时于身份块尾加一句"轴③主选按另一口径"。需要在 BTC 和 golden 数据上确认目前两者一致。
- [常见比例被读成规则] → 文字统一用"常见 / 指引"，JSON 用 `typical` 前缀，测试断言不出现"违规"。
- [轴②变长] → 身份对照用表格（每个情景一行）；(a) 内部只给价链；完整目标阶梯仍只进 JSON。
- [子级别下钻失败时 `narrative` 缺字段] → `buildAxis2Roles` 只依赖 cws 与主级别 K 线，不依赖下钻结果；形态相容性在缺数据时写"形态待明"。

## Migration Plan

两步分开提交：第一步（D1）独立可回滚；第二步（D2–D8）只触及叙述与渲染，回滚时恢复 `renderAxis3` 的挂载点和 `pullbackAfterUpgrade` 的旧签名即可。JSON 只做新增，下游读者不受影响。

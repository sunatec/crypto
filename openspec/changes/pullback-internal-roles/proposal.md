# Proposal

## Why

轴②「进行腿细化」里，回撤段（摆动极值 → 回撤真低点）的内部清单只在调整浪里找候选，文案统一写"均为三段式调整"。但在"这段是浪② / b 腿"的同一前提下，这段还可以是**单锯齿的 (a)**，而 (a) 必须是五浪（推动浪或引导楔形）。漏掉这个角色，会让报告前后不一致：

- 读法一的分支②写"只剩单锯齿（要求 (a) 浪为推动浪或引导楔形）"，但整段从来没有按五浪检验过，这条分支有没有依据，读者看不出来。
- 读法三（"已在真低点走完"）的风险没有交代：整段若是五浪，就不能单独构成一个完整的调整浪。
- 读法一的分支①（冲破 70% 线）只写了平台形和联合形，漏了单锯齿：单锯齿的 (b) 合法范围是 (a) 的 20%～100%，深 (b) 照样合规。
- 分支②没有写 (b) 的 20% 下限：反弹不到这条线就跌破真低点时，"(a) 在真低点结束的单锯齿"本身就不合规。

实例：BTC 2026-09-21～11-08 的 87395.67 → 79800 → 84898 → 76325.98 → 81196.01 → 73510，套引导楔形时 8 条硬规则 0 违规，用同一窗口单独分析时引擎主选也是"楔形（位置待定）"。可是 2026-11-09 的日线报告写的是"均为三段式调整"。

## What Changes

- 回撤段内部清单改为**在浪② / b 腿前提下按角色列出**：每个候选标出它在前提下的角色（整条浪②/b、平台形 (a)、单锯齿 (a)、双锯齿 (w)、联合形 (w)）。
- 候选池加入五浪类读法（推动浪、引导楔形），这类读法**只赋予"单锯齿的 (a)"这一个角色**。叙述写明：若成立，浪② / b 腿还没走完，真低点之后是 (b) 三波反弹（回撤 (a) 的 20%～100%、不越过摆动极值），之后还有 (c)。
- 不输出"新一轮下跌的第 1 浪"之类超出前提的读法，不改轴②的排名。
- 不再统一写"均为三段式调整"，也不再写"走完即到头"；有五浪读法时分别交代两类。
- 三锯齿等同族的不同形态不再被按族去重吞掉。
- 五浪读法附上收敛程度和楔形指引的命中情况，作为注记，不作为淘汰条件。
- 读法三（整段已走完）在整段存在五浪读法时注明：若为五浪，本读法不成立。
- 读法一的分支①：冲破 70% 线后，单锯齿（深 (b)）与平台形、联合形并列，靠之后 (c)/(y) 的走法区分。
- 读法一的分支②：加入 (b) 的 20% 下限（真低点 + 0.2×G）。反弹没到这条线就跌破真低点时，写明"(a) 在真低点结束的单锯齿"不合规，更可能是 (a) 或末段在延伸；整段内部没有五浪读法时，写明单锯齿这条路缺少依据。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `current-pullback-narrative`：竞争形态清单从"只列调整形态"改为"在浪②/b 前提下按角色列出，含五浪类的单锯齿 (a)"；高一级读法的状态①和状态②补充单锯齿的 (b) 范围（20% 下限、深 (b) 合规）；读法三补充五浪风险说明。

## Impact

- 代码：`analyze-wave-tree.js` 的 `analyzePullbackCompleted`（候选池、去重）、`renderPullbackLegDetail`（内部清单文案、读法一分支①②、读法三），以及高一级读法的线位计算处（新增 20% 线）。
- 输出：`_tree.md` 的"进行腿细化"一节文案会变化；`_tree.json` 的 `currentPullback.subDegree.rankedPatterns` 每项多出角色字段，高一级读法多出 20% 线。
- 测试：`tests/` 下与回撤叙述相关的回归测试需要更新快照，并新增 BTC 引导楔形实例。
- 测试文件：`tests/pullback-higher-degree.test.js`、`tests/wave-regressions.test.js` 引用了 `rankedPatterns` 或"均为三段式"文案。
- 下游：`advise.js` 不读取 `rankedPatterns`；JSON 只新增字段、不删除旧字段。

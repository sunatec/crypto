# Design

## Context

动机见 proposal.md 的 Why 一节。现状：

- `analyzePullbackCompleted` 调用 `decompose(completedFine, candles, [CORRECTIVE], 0, { beamK: 6, maxDepth: 2 })`，候选池只有调整类；之后按 `manual.patternType` 去重。单锯齿、双锯齿、三锯齿的 patternType 都是 `zigzag`，三锯齿因此被吞掉（双锯齿另有专门的挑选逻辑才得以保留）。
- `renderPullbackLegDetail` 取 `rankedPatterns.slice(0, 4)` 写"较符合 …"，再用正则 `/单锯齿|双锯齿|平台形/` 挑出前 3 个写价链，并固定写"均为三段式调整"；在没有高一级读法的分支里还写"走完即到头"。
- 高一级读法（读法一）只计算 70% 线、规则型上限、联合形上限、平台形上限，没有单锯齿 (b) 的 20% 下限。
- 文法里已经有现成的角色 `ROLE_IMPULSE_LEADING`（`impulse|leading`），对应 `['impulse-strict', 'diagonal-leading']`，正是单锯齿 a 浪所用的角色。

## Goals / Non-Goals

**Goals:**
- 整段内部清单按"浪②/b 前提下的角色"组织，五浪类读法只赋予"单锯齿的 (a)"。
- 读法一的分支①、②与读法三的文字，能和内部清单对上：哪个分支需要什么样的内部结构，清单里有没有。

**Non-Goals:**
- 不改轴②的情景排名，也不新增"前提之外"的情景（例如新一轮下跌的第 1 浪）。
- 不拆解真低点之后进行中反弹的内部结构（沿用现有规格）。
- 不引入书外的楔形淘汰阈值。

## Decisions

### D1 五浪类候选用 `ROLE_IMPULSE_LEADING` 单独拆一次
在原有 `[CORRECTIVE]` 拆解之外，再用 `[ROLE_IMPULSE_LEADING]` 拆一次同一组枢轴，参数相同（beamK 6、maxDepth 2），只保留无 severe 违规、无文法违规的候选。
- 不用 `[CORRECTIVE, DRIVING]`：DRIVING 还会带进终结楔形和扩散终结楔形，它们出现在 5/C 位置，不可能是 (a)，进了清单反而要再过滤。
- 用现成角色的好处是：所需子浪结构（推动浪 5-3-5-3-5、引导楔形 5-3-5-3-5 或 3-3-3-3-3）由既有文法负责，和轴①里"a 浪须为推动浪或引导楔形"的判定口径一致。

### D2 角色按形态静态映射
每个候选带一个 `roles` 数组，按 patternId 决定：

| 形态 | 角色 |
|---|---|
| 单锯齿 | 整条浪②/b、平台形 (a)、双锯齿 (w)、联合形 (w) |
| 双锯齿、三锯齿、平台形、联合形（双重/三重） | 整条浪②/b、平台形 (a)、联合形 (w) |
| 推动浪、引导楔形 | 单锯齿 (a) |

依据：浪② 不能是三角形（已由现有过滤保证）；平台形的 a、联合形的 w 须为三波；双锯齿的 w 须为单锯齿；单锯齿的 a 须为五浪。三重联合形另有读法二（已存在），映射里只标注角色，不重复叙述。
- 备选方案是在每个角色上各跑一次文法判定。代价是多次拆解，而结论与静态映射相同，因此不采用。

### D3 三锯齿单独成族，其余仍按形态族去重
只把三锯齿从锯齿族里拆出来，单锯齿、双锯齿、三锯齿各自保留。平台形的各子类（flat / flat-regular / flat-expanded）和双重 / 三重联合形仍按族合并：完全按 `patternId` 去重会把平台形子类全部列出来，只增加噪音。双锯齿原有的"挑端点为跨度极值、不与别族同链"的逻辑保持不变。"较符合"一句列出全部三段式形态名（不再截断到前 4 个），价链仍只展开单锯齿 / 双锯齿 / 平台形。

### D1a 五浪类单独存放，硬规则也须全过
五浪类候选放在 `subDegree.fiveWavePatterns`，不混入 `rankedPatterns`。`rankedPatterns` 还被高一级读法、读法三、末段延伸、轴②身份对照用作"整段内部的调整浪读法"，混入五浪会让这些下游误判。筛选上，除了无 severe、无文法违规，还要求 tier1 = 0（价格硬规则全过），否则同一组枢轴会冒出大量勉强的楔形。每种形态（推动浪、引导楔形）只取排名最前的一个。

### D4 楔形只做注记，不设淘汰阈值
书 §2.3 只要求楔形边界收敛，现有规格也禁止用书外指标定级。所以不对"收敛太弱"做淘汰，而是在五浪读法后面注明：
- 通道收窄比例 = 1 − (4 浪时的通道宽度 ÷ 2 浪时的通道宽度)，复用 `diagonal.pattern.boundaries-converge` 的计算口径；
- 楔形指引的命中情况（例如"3 短于 1、5 短于 3"未满足）。

读者据此自行判断这条读法的分量。

### D5 20% 线与 70% 线同基数
20% 线 = 回撤真低点 + 0.2×G，G 为摆动极值到真低点的价差，和 70% 线用同一个 G。依据：单锯齿规则 `zigzag.ratio.b-price-between-0.2a-and-a` 按价格计算。状态判定沿用现有三态，在状态①内再细分"未到 20% 线"和"20%～70%"。

### D6 分支①用内部清单来区分单锯齿和平台形
冲破 70% 线后，单锯齿（深 (b)）、平台形和联合形都可能成立。三者之后的 (c)/(y) 都可能是五浪，靠走法很难区分；更直接的区别在于 (a) 的内部结构：五浪对应单锯齿，三波对应平台形或联合形。所以分支①的文案要引用内部清单：清单里有五浪读法时写出单锯齿，没有时注明单锯齿缺少依据。

### D7 读法三的五浪风险说明
清单中存在五浪读法时，读法三追加一句：若整段为五浪（单锯齿的 (a)），浪② / b 腿还没走完，本读法不成立。没有五浪读法时不加。

## Risks / Trade-offs

- [楔形泛滥：几乎任何 6 个拐点的下跌都可能凑出合规楔形] → 只在文法和硬规则都通过时列出，并带上收敛比例和指引命中情况（D4）；角色限定为单锯齿的 (a)，不改轴②排名。
- [多拆一次带来的耗时] → 只拆已走完段，maxDepth 2，与现有调用规模相同；必要时可复用 `cache`。
- [文案变长] → 内部清单仍按"调整类 / 五浪类"两行写，价链合并规则沿用现有的同链合并。
- [回归快照大面积变化] → 只变"进行腿细化"一节和新增的 JSON 字段，其余章节的快照不应变化，作为验收条件。

## Migration Plan

纯输出变化，无数据迁移。JSON 只新增字段（`roles`、五浪注记、20% 线），旧字段保留。出问题时回退本次提交即可。

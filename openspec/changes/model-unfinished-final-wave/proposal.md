# 提案：顶层结构的「末浪未走完」也要能表达——修框架B在逆势反弹处失效、软化框架A的"完成"宣称

## Why

`rank-competing-wave-counts` 引入了框架B（区间延伸到 now），本意是表达"读法2"——当前走势可能是**更高级别、尚未走完的浪的内部子腿**，全局极值只是中继而非终点。但它有一个结构性缺陷：**框架B 只在 `now` 恰好落在顺势极值时才有效。**

`decompose` 要求形态的首尾枢轴类型与该形态的方向一致（下行调整须终结于 L，上行须终结于 H）。框架B 的区间是 `[全局极值 → now]`：

- `now` 落在**顺势新极值**（下跌中的新低 L）→ 终点=L，下行形态可终结于此 → 框架B 正常（曾产出"5浪下跌仍在走"）。
- `now` 落在**逆势反弹高点**（下跌中的 H）→ 终点=H，所有下行形态因"首尾类型不匹配"被否 → **框架B 返回空叶子、一个候选都没有**。

实证（BTC 1d，现价 79500）：

```
框架B区间: 起 H126296 → 止 H79500(prov=now)  净向下，但止点=H
→ 下行形态需终点=L，全被否 → 框架B 无候选
```

后果：**框架A 的"大跌完成于全局极值 57718"成了唯一被展示的读法，过度宣称"已完成"。** 而用户提出的完全合规的读法——`126296→84400(W) / 84400→97964(X) / 97964→now(Y 还没走完)`，即"57718 只是 Y 内部的拐点、当前反弹是 Y 的中段回撤、之后还有新低"——**结构上根本表达不出来**。它和框架A 共用同一组宏观点（126296/84400/97964/57718），分歧仅在于**末浪(c/Y)到 57718 是走完了、还是还在延伸**；而这恰恰在"当前正处反弹"时最该提示。

## What Changes

对 `analyze-wave-tree.js`（`analyze-kline-wave.js`、`analyze-wave-manual.js` 零改动）：

1. **修框架B的终点处理（核心，探索选项②）**：当 `now` 处于逆势极值（与顶层净方向的终结类型相反）时，框架B **不再强行让形态终结在 `now`**；而是把顶层结构拟合到**最后一个顺势极值**（如 57718），并把该结构的**最后一个宏观浪标为"进行中"**——其终点是投影的未来极值（跌破 57718 的新低），当前逆势走势是这条末浪内部的回撤。这样"末浪未走完、还有新低"就能作为一条真正可排名的竞争数法出现。

2. **软化框架A的"完成"宣称（探索选项①）**：框架A 不再无条件标"✅已完成"。末浪终结于全局极值，但整段是否真正完成取决于该极值是否被跌破/升破；改标为"完成（待确认）"，并注明"若跌破/升破 X 则末浪延伸、还有新低/新高"。

## Impact

- 改动文件：`analyze-wave-tree.js`（框架B 构建逻辑、末浪进行中标注、排名表框架A/B 的标签与投影）。
- 涉及能力：`wave-count-tree`（框架B 终点行为、末浪进行中语义、框架A 完成度措辞）。
- 不改：数据源、CLI、`rank-competing-wave-counts` 已交付的搜索补全/两段式beam/排名去重等。
- 兼容：框架A 的宏观骨架不变，仅完成度措辞变化；框架B 从"逆势反弹时空缺"变为"能给出末浪进行中的竞争读法"。

## 非目标

- **不改形态集**、不放开超出现有 `maxDepth` 的深层嵌套。
- **暂不做探索选项③**（把"57718 之后的反弹"在"新结构 X/B"与"未完成末浪内部回撤"两种身份间做完全统一的并列竞争）——先看 ② 是否已足够表达；③ 若确有必要另立 change。
- **不引入书外指标**。

# 提案：语法角色判定改为「能否胜任」而非「最佳性格==所需」——消除歧义腿的假违规

## Why

`decompose` 的文法（grammar）检查判定一条子腿是否违反父浪要求的角色时，用的是
「这条腿的**最佳性格**（`legCharacter().character`）是不是所需角色」：

```js
const requiredChar = childRole === DRIVING ? 'driving' : 'corrective';
const lc = legCharacter(childFine, candles, depth + 1, opts);
if (lc.character && lc.character !== requiredChar) grammarViolations += 1;
```

而 `legCharacter` 有一条**「驱动优先」**的平局裁决：只要一条腿能干净地走成五浪
（`dClean`），就判为 `driving`，**哪怕它同样能干净地走成三波**。这条平局裁决本意是防
「规则稀少的调整形态把干净推动腿误判成调整」，但副作用是：**当一条歧义腿（既能干净读成
五浪、也能干净读成三波）落在一个要求它是调整浪的位置时，会被误报违规。**

实证（用户手数的双锯齿 `126296→80524(W) / 80524→97964(X) / 97964→57718(Y)`，`--count` 打分）：

```
X 连接浪 (80524→97964)：当五浪拆 违规×0；当三波拆(单锯齿) 违规×0  ← 两种都干净
Y 末浪   (97964→57718)：当五浪拆 违规×0；当三波拆(单锯齿) 违规×0  ← 两种都干净
```

双锯齿语法要求 X、Y 是调整浪（3波）。它俩**明明能当干净的3波**，却因"驱动优先"先被判成
五浪，于是报了两条「该3波却像5浪」的违规——**假阳性**。结果这套双锯齿被记为 **违规×3**
= [y/w 比例差1% + X假违规 + Y假违规]；**去掉两条假违规后只剩 违规×1**（仅 y 略短于 w），
本该排到很靠前，却被语法过严压了下去。

## What Changes

改 `analyze-wave-tree.js` 的 `decompose` 文法检查（`analyze-kline-wave.js`、
`analyze-wave-manual.js` 零改动）：

**文法违规的判据从「最佳性格 != 所需角色」改为「这条腿无法胜任所需角色」。** 一条腿能
胜任「调整浪」角色，当且仅当它存在**干净的调整拆解**（`correctiveNode` 的 tier1=0）；能胜任
「驱动浪」角色，当且仅当存在干净的驱动拆解（`drivingNode` 的 tier1=0）。歧义腿（两种都干净）
可胜任任一角色，不计违规。仅当所需角色的干净拆解**不存在**时才算文法违规。为不漏判
「两种都拆不干净」的情形，退回旧口径（用最佳性格判断）。

## Impact

- 改动文件：`analyze-wave-tree.js`（`decompose` 里 grammar 违规的计算；可能顺带在
  `legCharacter` 返回里补充 `canDrive`/`canCorrect` 便于判断，不改其 `character` 输出）。
- 涉及能力：`wave-fit-scoring`（文法违规判据）。
- **影响面较大**：许多含"歧义腿"的候选会从"带文法违规"变为"干净"，排名会重排——须以金标准
  报告做前后对照，确认没把真正该违规的（如"要求调整、却只能干净走五浪、根本走不成三波"）
  漏掉。
- 兼容：`--count` 打分、排名表、结论各节的口径一致受益（假违规消失）。

## 非目标

- **不改各形态的硬规则本身**，只改"子腿角色是否违规"的判据。
- **不改 `legCharacter` 的 `character` 输出**（它作 5波/3波 性格研判仍有别处在用）；只改
  `decompose` 如何用它来判文法。
- **不改"驱动优先"用于性格研判的其它场景**（如现状研判里判反弹是5波还是3波）。

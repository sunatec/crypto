## Why

父级身份（当前反弹是 XX 连接浪、B 浪还是新推动）目前只凭窗口内的回撤比例推断，`ai.md` 要求说明的「反弹针对哪一段」因此缺少更大结构的依据。完整的自上而下数浪（书 §3.10 月线→周线→日线链）经探查不宜做：Coinbase 数据起点不是品种诞生（BTC 缺 2010–2015 年），顶层读法过多且难以向下验证。但在周线上自 §3.12 的价格 0 起只看最大一级，就能得到有分量的结论：调整浪读法违反 §3.12「自 0 起必为驱动」直接排除；驱动浪读法按类别归纳后，每一类对当前行情的含义（当前大跌修正的是哪一段）都是确定的。BTC 实测存活两类——「126296 为从 0 起完整推动浪的 5 浪终点」（如 0→64899→15460→109358→74421→126296）与「126296 为 3 浪终点、4 浪进行中」。

（更正：探查阶段曾得出「完整驱动浪 0 合规」，那是把价格 0 起点的百分比规则当成除零失败造成的误判，见设计决策 3a。）

## What Changes

- 在大级别背景已取得的全部日线（已截取疑似乌龙针）上聚合周线，于首根之前加价格 0 虚拟点，枚举最大一级的驱动浪读法，按「历史极值在顶层是什么」分成类别：
  - 完整驱动浪终点（从 0 起的 1 浪或 5 浪已完成，当前为比它高一级的调整）；
  - 3 浪终点、4 浪进行中（1、2、3 浪已完成）。
  调整浪读法按 §3.12 不列入。每类给出合规读法数、1 浪终点与 2 浪低点的取值范围、所用硬规则，以及被全部排除的类别及排除原因。
- 每个存活类别说明：当前窗口结构在顶层属于哪一浪、修正的是哪一段；XX / B / 新推动三种父级情景在该类别下各是什么、针对哪一段；失效条件（如 4 浪不得跌破 1 浪顶，按 1 浪顶取值分档）。
- 报告轴①在「大级别背景」之后新增「顶层读法（自价格 0，周线）」子块，父级候选表每个候选附一句顶层类别下的身份；JSON 新增 `topLevel`。始终声明数据起点并非品种诞生。
- 顶层读法**只作证据**，不改变任何排名或主选；背景关闭或不可用时顶层读法同样不可用。

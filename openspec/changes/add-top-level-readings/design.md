## Context

- 大级别背景（`higher-degree-background`）已取得全部日线并截取疑似乌龙针，生成周/月线、级别阶梯，但不数浪。
- 父级身份由 `deriveParentDegree` 在 X / B / 新推动之间按窗口内回撤比例与反弹子浪性格排名，`renderParentRole` 呈现。
- 引擎有两种框架：A（区间内结构已完成）与 B（末浪进行中）。「1、2、3 浪已完成、4 浪进行中」这种只走了一部分的推动浪两者都不覆盖；当前浪模板 T1–T4 对窗口内做过类似的部分结构枚举。

探查（scratchpad，BTC/ETH Coinbase 全部历史，周线，自价格 0）：

| 读法 | BTC（ATH 126296） | ETH（ATH 4956） |
|---|---|---|
| 0 → ATH 完整驱动浪 | 探查时 0 合规——**误判**：价格 0 起点的 §3.16 百分比被当作除零失败（见决策 3a）。按 +∞ 判定后周线 63 个候选中 2 个存活：0→64899→{15460, 49050}→109358→74421→126296 | 楔形 0→3582→880→4094→2116→4956 合规 |
| 现有 `buildCountTree` 主选 | 单锯齿 / 平台（违反 §3.12） | 楔形 |
| ATH = 3 浪终点、4 浪进行中（仅价格规则） | 67 个，1 浪顶 298–52945、2 浪低点 198–15460 | 73 个 |

结论：逐条列读法没有意义（67 个只在 1、2 浪取点上不同），但「类别」层面的结论稳定且有排除力。耗时：周线 `decompose` 约 2–4 秒。

## Goals / Non-Goals

**Goals:**
- 给出自价格 0 起最大一级的存活类别与被排除类别，并把每个存活类别翻译成对当前窗口与父级情景的含义（针对哪一段）。
- 只作证据，诚实披露数据起点与歧义（取值范围、待定数）。

**Non-Goals:**
- 月线→周线→日线的完整数浪链与跨级别一致性（完整 A3）。
- 嵌套级别（如 ATH 为 3 浪内部的 iii 浪、当前为 iv 浪）——只看自 0 起的最大一级，报告注明。
- 「1、2 浪已完成、3 浪进行中」「2 浪进行中」等其他部分结构：ATH 之后已出现大幅回落，这些读法要求 ATH 本身是进行中浪的一部分，与「4 浪进行中」「完整驱动浪后调整」在对当前行情的含义上重合或需更深嵌套；先不枚举，日后按需要扩展。
- 楔形的「4 浪进行中」变体（楔形 4 浪须进入 1 浪区域，规则不同），先不枚举并注明。
- 用顶层证据改变排名；补 2015 年前的外部数据。

## Decisions

### 1. 输入：复用背景的全部日线与扎针处理

顶层读法依赖背景：`loadHigherDegreeBackground` 已取得全部日线并按 `spike-detection` 截取疑似乌龙针；在同一份截取后的日线上聚合周线（`transformCandles(…, TIMEFRAMES['1w'])`），首根之前插入一根 OHLC 全为 0 的虚拟周线。背景不可用时顶层读法不可用，不单独取数。有量扎针（如 ETH 2017-06-21 的 0.10）按 §3.15 保留，可能成为 2 浪低点，报告列出。

### 2. 「完整驱动浪」类别：复用引擎

对周线枢轴中「虚拟 0 → 历史极值」这一段调用 `decompose(…, [DRIVING], 0, {maxDepth: 4, beamK: 6})`，取全部候选；`tier1 === 0` 为合规（子浪角色待定计入待定数），其余按首条违规原因计数作为排除原因。

### 3. 「4 浪进行中」类别：确定性枚举 + 可判定规则

1 浪终点 P1 与 2 浪低点 P2 互相约束（P1 为 [0, P2) 的最高价，P2 为 (P1, ATH) 的最低价），因此只需遍历周线高点枢轴作为 P1 候选，P2 随之确定，再验证约束成立——组合数等于高点枢轴数（BTC 约 100），无需显著性短名单。对每个 (P1, P2) 检查：

| 规则 | 依据 | 判定 |
|---|---|---|
| 2 浪回撤 ≥ 1 浪 20%，且不跌破 0 | §3.18.2、§1.5 | 违规即排除 |
| 3 浪终点（ATH）高于 P1 | §1.5 | 违规即排除 |
| ATH 之后至今最低价 > P1（4 浪不入 1 浪区域） | §1.5、§3.17 | 违规即排除 |
| 4 浪至今时间 ≤ 3 浪时间 2 倍 | §3.21 | 违规即排除（只会随时间变得更严） |
| 3 浪不是最短 | §1.5 | 待 5 浪，列为待定 |
| 子浪角色：1、3 浪驱动，2 浪调整（周线 `evaluateLegRole`，maxDepth 3） | 文法 | invalid 排除，pending 计数 |

推动浪的规则直接写成该枚举专用的判据（与 `impulse-strict` 手册同源的阈值），不复用手册是因为手册要求 6 个点且会把 4、5 浪规则一并判定。

### 3a. 价格 0 起点的价格运动百分比按 +∞

§3.16「价格运动百分比 =（最高 − 最低）÷ 最低」在最低为价格 0 时除以 0。按定义的极限，从 0 涨到任何正价的百分比为 +∞，而不是不可计算。规则「3 浪的价格运动百分比不能同时小于 1 浪和 5 浪」在 1 浪为 +∞ 时等价于「3 浪不得小于 5 浪」，照常判定。

- 只对带 `virtual: true` 的价格 0 虚拟起点生效；真实价格输入行为不变。
- 备选一：判失败（原引擎行为）。否决——把除零当违规，探查阶段正是因此误判 BTC 完整驱动浪 0 合规。
- 备选二：判待定（实现初版）。否决——规则在 +∞ 下可判定，待定会掩盖结论；还会让子浪层面（如 1 浪 0→69000 自身是从 0 起的推动浪）该违规的读法逃过检查。
- 实测：BTC 0→64899→15460→109358→74421→126296 中，3 浪 15460→109358 为 607%、5 浪 74421→126296 为 69.7%，通过；以 69000 为 1 浪终点的读法，其 1 浪内部在同一规则下拆不出合规推动浪，被子浪文法排除。

### 4. 类别汇总与含义映射

- 窗口结构 S→E 与顶层的对应：按时间找 S、E 所在的顶层浪。对「4 浪进行中」：若 S 为 ATH，则窗口下跌是 4 浪的第一段，修正的是 3 浪（P2 → ATH，P2 给范围）；若 S 早于 ATH，按所在浪如实描述。对「完整驱动浪」：窗口下跌属于比 0→ATH 高一级的调整的第一段，修正的是整个 0→ATH。
- 父级情景映射（固定文案模板，数字代入）：

| 父级情景 | 4 浪进行中 | 完整驱动浪之后 |
|---|---|---|
| XX 连接浪 / B 浪 | 4 浪内部的 x / b，针对窗口下跌（4 浪第一段） | 高一级调整内部的 x / b，针对窗口下跌 |
| 新推动 | 5 浪起步，前提 4 浪已在 E 完成 | 新一轮驱动起步，前提高一级调整已在 E 完成 |

- 失效分档：把存活读法的 P1 由高到低排序，给出若干价位「跌破 X 会淘汰 n 个读法」，最低一档即「类别整体失效」。
- 代表读法取 P1 最高者（最接近当前价位、约束最强）。

### 5. 呈现

- 轴①「大级别背景」之后新增「顶层读法（自价格 0，周线）」：数据起点声明 → 类别表（类别、合规/待定/排除数、P1/P2 范围、主要排除原因）→ 每个存活类别一段含义说明与失效分档 → 嵌套与未枚举结构的说明。
- `renderParentRole` 表后（背景摘要之前）为每个候选加一句「顶层：…」，取自第 4 节映射；无存活类别时写明无顶层依据。
- JSON 顶层 `topLevel`：`{available, reason?, dataOrigin, families:[{key, legal, pending, excluded, excludedReasons, p1Range, p2Range, representative, windowRole, parentMapping, invalidationTiers}]}`。

## Risks / Trade-offs

- [数据起点并非价格 0，可能把多个级别压成一段] → 每处都声明；只用类别层面的结论，不对 1 浪内部做细分判断。
- [只看最大一级会漏掉嵌套读法] → 报告注明；嵌套读法对当前行情的含义（iv 浪修正 iii 浪）可由读者对照级别阶梯理解。
- [周线子浪角色检查多为待定] → 待定不排除，只计数；结论主要来自价格硬规则，这些规则在周线上已可判定。
- [ETH 有量扎针 0.10 成为 2 浪低点] → 按 §3.15 本应如此，报告点名。

## Migration Plan

新增 JSON 字段与报告子块，父级表新增一句；其余输出不变。背景关闭时顶层读法同样关闭。

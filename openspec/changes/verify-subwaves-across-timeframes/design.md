## Context
同步 decompose 只消费一个周期；当前回撤下钻不进主计数。用户授权方案二：竞争候选共享跨周期证据，并修正已确认的几何与身份问题。

## Goals / Non-Goals
**Goals:** 日线→4h→1h 按需验证位置角色；固定端点；未知不冒充通过；所有竞争候选复用相同验证器。
**Non-Goals:** 不强制某种 BTC 数法胜出，不无限下钻，不修改旧 manual 数据源或安装依赖。

## Decisions
1. 保留同步引擎，增加异步 buildVerifiedCountTree。先加载覆盖母级区间及完整端点桶的共享小时行情，再按候选子腿时间窗惰性验证；4h 由相同小时数据聚合。同步搜索通过验证器取得角色证据，各竞争候选与指定数法复用缓存后评分。使用母级区间作为候选窗口的覆盖范围，避免按候选重复发起网络请求。
2. 位置证据分 verified/pending/invalid。小周期判据通过但更深角色未证实则保持 pending；点数、搜索或深度上限、缺失行情及 API 失败均 pending。明确价格违规继续计硬规则。保留旧同步调用的硬分兼容，并让序列化暴露 pending；CLI 启用证据模式。
3. 使用时间戳、周期、角色和价格作证据键，跨周期节点保存周期及独立索引。母级端点 K 线窗口完整取数，再定位小时极值；验证窗口禁止埋入更高/低价或倒序锚点。不将下级索引当主级索引。
4. 有限验证到 1h，波浪级别与 K 线周期分开。未穷尽搜索不作绝对证伪；候选只能在已检查的粒度与结构范围内标通过。缓存与 beam 限制计算量，达到上限透明待验。
5. 排名在硬规则之后比较待验比例；已通过、无硬伤的候选优先。无确定合规方案时明确暂定。所有下级验证来自相同数据和规则。
6. 对楔形增加 1–3、2–4 边界真实收敛；从唯一父级候选派生反弹身份、目标和之后浪位，消除 B/X/XX 混用。

## Risks / Trade-offs
- 小周期噪声和算量增加 → 只核对角色窗口、复用取数及角色缓存、记录分辨率与搜索范围。
- 日 K 时间戳不是极值时刻 → 完整读取端点日，定位小时极值后裁剪；未匹配就待验。
- 严格证据可能没有全通过者 → 展示暂定主选及未决证据，不强制黄金样本形态。

## Migration Plan
增加兼容 JSON 字段；CLI 默认验证至 1h，提供 --verify-tf off 离线行为开关但仍展示未验证状态。保留股票日线模式并明确未跨周期验证。更新 README 和旧楔形黄金断言。

# 提案：宏观腿端点必须是其跨度内的真极值——堵住"顶没顶到位"的 lower-high 骨架

## Why

`macroAlternates`（上一轮修"下降连接浪"时加的几何校验）只检查**相邻宏观点之间**的高低关系
（内部 H 高于左右相邻宏观点、L 低于左右相邻）。它没检查**一条宏观腿内部（两个宏观点之间的
细枢轴）有没有比端点更极端的点**。于是仍会出现：一条去 H 的腿，端点是个 lower-high，而腿的
跨度内部藏着一个更高的高点。

实证（BTC 1d，"现在走到哪了"的上冲段 a-b-c）：

```
a 段: 57718(7/1) ───▶ 65705(7/27)
  内部走过: 64669(7/10) → 65560(7/15) → 66924(7/21,最高) → … → 65705(7/27,收尾)
                                         ▲ 66924 比 a 段收尾的 65705 还高
```

a 段收在 65705，但它跨度内 7/21 有个更高的 66924——**a 顶没取在真极值**。这和更早发现的
"备选2 的 b 浪收在 82814、内部却埋着更高的 97964"是同一类问题：宏观腿端点取了个更低的高点
（或更高的低点），只因这样能让整套形态评分更干净。读起来不自然、也不符合"宏观拐点应是该段
主极值"的常识。

## What Changes

改 `analyze-wave-tree.js`（其余文件零改动）：

新增几何硬校验 `legEndpointsSpanExtreme(pts, segFine)`——对每个内部宏观点，检查其在
「左右相邻宏观点之间的所有细枢轴」里是否为真极值：去 H 的端点须严格高于该跨度内每一个细枢轴、
去 L 的端点须严格低于。任一宏观点非其跨度极值即淘汰该候选。它比 `macroAlternates` 更强（后者
只比相邻宏观点，本校验比整段跨度内的细枢轴），实际**包含** `macroAlternates`；与它并列放在
`decompose` 候选校验处（`macroAlternates` 作 O(n) 快筛先跑，本校验再扫细枢轴）。

## Impact

- 改动文件：`analyze-wave-tree.js`（`decompose` 候选校验；新增 `legEndpointsSpanExtreme`）。
- 涉及能力：`wave-count-tree`（顶层/子结构候选的几何有效性）。
- **影响面**：会淘汰一批"顶没顶到位"的候选，排名重排——须金标准前后对照，确认淘汰的都是
  lower-high/higher-low 退化骨架，没误伤合法形态（收缩/扩散三角、扩散平台等经核仍满足）。
- 兼容：与 `macroAlternates`、`grammar-role-fulfillment` 叠加；`--count`、排名表、结论各节一致受益。

## 非目标

- **不改形态硬规则本身**，只加"宏观端点须为跨度极值"的几何有效性闸门。
- **不替换 `macroAlternates`**（保留作快筛，虽被本校验包含）——降低回归风险、语义分层清晰。
- 不处理"端点与内部极值同价（并列）"为违规（用严格不等号，仅内部**严格**更极端才淘汰）。

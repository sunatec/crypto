# 设计：宏观腿端点须为跨度内真极值

> 来自探索：用户发现 a 段收在 65705、内部却有更高的 66924。仅改 `analyze-wave-tree.js`。

## 1. 缺陷定位

`macroAlternates(pts)` 只看宏观点两两相邻：
```
内部 H 须 > 左右相邻宏观点；内部 L 须 < 左右相邻宏观点。
```
它保证了"方向真反转"（修掉了下降连接浪），但**没看一条腿跨度内部的细枢轴**。所以：
```
a 段 57718(L) → 65705(H)，中间藏着 66924(H) > 65705 —— macroAlternates 看不到（66924 不是宏观点）
```

## 2. 更强的校验：跨度极值

新增 `legEndpointsSpanExtreme(pts, segFine)`：对每个内部宏观点 `pts[i]`，取其左右相邻宏观点
的索引窗口 `(pts[i-1].index, pts[i+1].index)`，检查 `segFine` 里落在该窗口内的每个细枢轴：
```
pts[i] 为 H：窗口内不得有细枢轴价格 > pts[i].price
pts[i] 为 L：窗口内不得有细枢轴价格 < pts[i].price
```
任一违反 → 该候选淘汰（硬，`continue`，与 `macroAlternates` 同处）。

**为什么它包含 macroAlternates**：相邻宏观点 `pts[i-1]`、`pts[i+1]` 本身就是 segFine 里的细枢轴、
落在窗口边界；本校验对窗口内所有细枢轴（含它们）要求端点为极值，故自动满足 macroAlternates。
保留 macroAlternates 只为 O(n) 快筛先行、降低本校验（要扫 segFine）的调用量。

## 3. 合法形态为何都满足

- 收缩三角：highs 递降 b>d，但 d 仍是它那段（c→e 之间）的最高 → 满足。
- 扩散三角/扩散平台：b 超越，但 b 仍是其窗口内最高 → 满足。
- 推动/锯齿：每个宏观拐点本就是其局部主极值 → 满足。
只有"用更低的高点/更高的低点当端点、把真极值埋进腿里"的退化骨架会被淘汰——正是要堵的。

## 4. 影响面与风险

- 排名重排：一批"顶没顶到位"的候选被淘汰，主选/备选可能变。
- 风险1（误伤）：某些复杂调整里 b 浪内部短暂超越端点？——用严格不等号，只淘汰"内部**严格**更
  极端"的；且这类"端点非极值"的读法本就不自然，淘汰是对的。金标准回归兜底。
- 风险2（性能）：每候选多扫一遍 segFine 窗口；segFine 每段有限、且在 `macroAlternates` 快筛后
  才跑，成本可控。
- 风险3（金标准漂移）：现有 golden 断言须不破（顶层起锚、进行中腿、序列化、现状研判、Markdown）。

## 5. 验证要点

- "现在走到哪了"的上冲段 a 段端点须落在真极值（现应取 66924 或更高，不再是 65705）。
- 单测：构造一条端点非跨度极值的腿（内部有更高高点）→ `legEndpointsSpanExtreme` 判 false；
  端点即极值 → true；含收缩三角样例 → true（不误伤）。
- 金标准 10 条不破；1d/1h 端到端无 undefined/NaN、性能正常。

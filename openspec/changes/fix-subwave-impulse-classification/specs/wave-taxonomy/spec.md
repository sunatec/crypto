# wave-taxonomy

## ADDED Requirements

### Requirement: 子浪驱动/调整性须经实证判定
系统判断一段子浪属于「驱动浪形态」还是「调整浪形态」时，SHALL 基于**实际的推动浪验证**（在该子浪的细枢轴上尝试套用推动浪/楔形验证手册并要求其通过全部规则），而 MUST NOT 仅以「子枢轴数量达到阈值」作为判定「驱动浪」的充分条件。当一段子浪内部无法验证出任何通过全部规则的推动浪/楔形，或存在明显的子浪重叠时，SHALL 判定为「调整浪形态」。

#### Scenario: 长且重叠的复杂上行腿判为调整浪
- **WHEN** 一段上行子浪内部包含多个反复重叠、回撤突破前一同向子浪起点的摆动，且无法验证出通过全部规则的推动浪
- **THEN** 该子浪被判定为「调整浪形态」（`impulseLike = false`），即使其子枢轴数量 ≥ 6

#### Scenario: 干净五浪腿判为驱动浪
- **WHEN** 一段子浪内部能验证出一个通过全部推动浪规则的 1-2-3-4-5 结构
- **THEN** 该子浪被判定为「驱动浪形态」（`impulseLike = true`）

#### Scenario: 判定不依赖单纯的枢轴计数
- **WHEN** 两段子浪子枢轴数量相同，但其一是干净五浪、另一是重叠复杂调整
- **THEN** 前者判为驱动浪、后者判为调整浪（判定结果不因二者枢轴数相同而相同）

### Requirement: 子浪结构判定不得无限递归
子浪驱动/调整判定 SHALL 限定为单层校验：评估子窗口推动浪/楔形时只使用基于价格/比率/时间几何的规则，MUST NOT 再次触发同一子浪结构判定，避免无限递归与性能退化。

#### Scenario: 单层校验不下钻
- **WHEN** 对某子浪做驱动/调整判定
- **THEN** 其内部推动浪校验只进行一层，不再对更细一层子浪递归调用同一判定

# 提案：以「验证手册」内核重构波浪分析引擎（P1）

## Why

现有 `analyze-kline-wave.js` 把所有判据（结构、交替、量能、RSI 背离等）揉进一个**加权综合分**。这与《波浪理论详解》（柳玉冬）所依据的艾略特/普莱切特原旨方法相冲突：

- 书的方法是**否定法**：浪型的「规则（Rules）」是**硬性闸门**，违反任意一条即淘汰该假设；「指引（Guidelines）」才是软性、用于给幸存候选排名。当前的加权分会让"破了铁律的坏假设"仅仅被扣一点分，仍可能排到第一，输出不可解释、不可反驳。
- 书反复强调三个一等度量——**价格（price，起点→终点）**、**运行总量（gross，所有子浪最低→最高）**、**价格运动百分比**——并规定不同浪型的比率要量哪一个（如"平台形 b 浪回撤 a 浪 70%"量的是**运行总量**）。现脚本没有显式区分「价格」与「运行总量」。
- 书第 00 章明确"不借助 KDJ、MACD、均线系统"，而现脚本使用 RSI 背离，偏离原旨。

## What Changes

**新建一个独立分析器脚本**（工作名 `analyze-wave-manual.js`），实现书的「验证手册」内核。**`analyze-kline-wave.js` 保持零改动**，两者并存、可对照。

P1 只做「度量与验证内核」，交付：

1. **一等度量层（wave-measurement）**：为任意浪型/子浪计算 `价格 / 运行总量 / 价格运动百分比`，并明确每个比率判据该以哪一个为基准。复用老脚本的取数与枢轴检测逻辑（Coinbase K 线、ATR 过滤 ZigZag）。
2. **验证手册引擎（wave-verification-manual）**：Rule / Guideline 数据模型；每种浪型 = `{ rules[], guidelines[] }`，按书的 6 层顺序（浪型规则→比率规则→时间规则→浪型指引→比率指引→时间指引）排列。评分改为**先否定后排名**：任一 Rule 失败即淘汰候选；幸存候选按命中的 Guideline 数量/权重排名。
3. **P1 浪型手册（wave-taxonomy 子集）**：把老脚本已覆盖的 **推动浪（含引导/终结楔形 diagonal）**、**单锯齿（5-3-5）**、**平台形（基础版，运行总量口径）** 三类改写为手册形态，作为引擎的首批实现样例与回归基准。
4. **RSI 降级**：新脚本默认不产出 RSI 背离判据；如保留则仅作旁注、不参与否定或排名。

## Impact

- 新增：`analyze-wave-manual.js`（新脚本）及其单元/回归测试。
- 新增 specs：`wave-measurement`、`wave-verification-manual`、`wave-taxonomy`。
- 不改：`analyze-kline-wave.js`、数据源、老脚本的 CLI 与 HTML dashboard。
- 新脚本 CLI 尽量复用老脚本参数命名（`--product/--tf/--start/--end/--out/--report` 等），降低迁移成本；`--rsi-period` 不再默认启用。

## 分期与非目标

**本提案仅含 P1。** 以下为后续独立变更，不在本提案范围：

- **P2 补全浪型库**：平台形三子类（规则/扩散/顺势，运行总量 70%/200% 口径）、收缩三角形 a-b-c-d-e、区分单(5-3-5)/双(3-3-3)/三锯齿、联合形、按位置区分引导 vs 终结楔形。
- **P3 工具与级别**：艾略特通道（平行/收缩/扩散）一等化、斐波回撤/扩展按书取点规则、斐波时间周期 + 共振日、级别（0/1/2 嵌套）标注与"月→周→日"跨级验证顺序。

**非目标（P1）**：不改数据源与 CLI 数据流、不做 HTML dashboard 视觉改版、不引入书之外的任何技术指标、不实现 P2/P3 的新浪型。

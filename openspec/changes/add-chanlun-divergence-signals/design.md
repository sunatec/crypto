# Design

## Context

动机见 proposal.md。现状：

- `chanlun_original.pine` 的形态 CORE 每根收盘 K 线按 L0 → Z1 → R1 → Z2 → R2 → Z3 → R3 推进（R-005），确认对象只追加；未收盘 K 线在隔离副本里预览。
- Z 关闭事件已带离开部件、回抽部件与关闭方向（E-010）。R 完成按结构确立路径（R-002～R-006），不检查背驰。
- 绘图走统一注册表与全局配额；5,000 根三层压力验收已在当前 CORE 通过。
- 约束：不能把绝对 K 线编号当作 series 历史偏移；不请求其他周期；单文件、不依赖 Pine 库。
- 原文：MACD 辅助判断见第24、25课；盘整背驰第27课；背驰的再分辨第37课；补习课第43课；小级别背驰与大级别转折第44课；三类买卖点第20、21、53课；区间套第61课。2026-11-11 补查记录了 R 端点与第一类买卖点之间的差距。

## Goals / Non-Goals

**Goals:**
- 信号模块只读消费形态内核的已确认对象，不改变任何形态确认结果。
- 每个信号都能回答：用了哪条规则、比较了哪两段、各段面积多少、何时发生、何时确认。
- 历史、实时、重载三种路径下确认信号一致。

**Non-Goals:**
- 区间套的多周期精确定位（需要请求低周期数据，违背单图约束）；只在研究视图提示“可用低级别区间套细化”。
- 修改 R 完成规则。是否改为以背驰为门槛，由诊断统计结果决定，另开变更。
- 策略回测、下单、仓位管理。

## Decisions

### 1. 信号层挂在每层 R 之后，只读

每根收盘 K 线的同批顺序扩展为 L0 → Z1 → R1 → D1 → Z2 → R2 → D2 → Z3 → R3 → D3。Dn 只读取本层已提交的 Z、R 事件和下层已提交部件，不向任何形态模块回写。

- 备选：独立第二个指标，通过 `input.source` 读取第一个指标的输出。放弃原因：只能传少量 series，传不了结构对象，确认时刻也无法对齐。

### 2. MACD 面积用前缀和按时间查找

每根已收盘 K 线追加 `(time, cumPos, cumNeg, dif, dea)` 到有界数组，容量跟随计算窗口。任一段的面积等于两端前缀和之差，起止时间按二分查找定位，不使用 `bar_index` 偏移。数组回收与窗口回收同步，并纳入资源预算；被回收区间内的段标记为“面积不可用”，不再参与比较。

- 备选：在每个部件确认时逐根回溯求和。放弃原因：部件端点常早于确认时刻，回溯要按 K 线偏移访问历史，违反约束，代价也随段长线性增长。

### 3. 比较段由结构 ID 决定（2026-11-11 已按用户裁定冻结，见 rules.md D-001～D-004）

- 趋势背驰：A 为前一中枢 Z(k−1) 的离开部件起点，到最后中枢 Zk 首个形成部件起点之间的部件链（Zk 以回抽部件为种子，所以通常就是离开部件 dep(k−1) 一个部件；原草案“回抽部件结束”起算会得到空或负区间，已改）。C 为 Zk 的离开部件，C 确认时即提交，不等回抽。每个中枢至多一个。
- 盘整背驰：中枢集只有一个中枢时，比较进入段（紧邻中枢首个形成部件之前、与离开部件同向的部件，可属上一条走势）与离开部件。没有同向进入段则不产生信号。
- 创新高（低）为硬条件（原文 C37-96、C61-154）：C 的终点价严格越过 A（盘整背驰为进入段）的范围极值；WD-255-46 为 editorial，不采用。面积 C 小于 A 为硬条件；黄白线回拉零轴、黄白线不创新高只作研究信息（D-004）。

### 4. 买卖点

- 第一类：确认的趋势背驰端点，即 C 段端点。
- 第二类：第一类之后的反向次级别走势完成，再出现首个同向次级别走势完成，且其端点不越过第一类价格；确认时刻为该同向部件的确认时刻。
- 第三类：直接取 Z 关闭事件的回抽部件端点，与 E-010 的触边约定一致（触边算回到中枢，C20-43 中心定理一）。
- 盘整背驰点单列类型，不冒充第一类。

### 5. 去重、预览与提醒

- 信号 ID 由层级、类型和依赖结构 ID 组成；已提交 ID 存入有界集合，重复执行同一 K 线不再提交。
- 预览沿用现有隔离副本：候选信号用空心标记，不写入确认流。
- 提醒用 `alert()`，只在 `barstate.isconfirmed` 且当批新提交的信号上调用，消息为结构化文本。用户在 TradingView 里建一条“任何 alert() 调用”的提醒，按层级和类型的开关由输入项控制。
- 备选：`alertcondition()`。放弃原因：消息不能带动态价格和 ID，而且每种组合都要单独建一条提醒。

### 6. R 端点诊断

R 完成时记录端点时间；同层第一类买卖点确认时比对端点时间。端点首次出现在研究视图时先标为“待比对”，之后按比对结果改为“已背驰确认”或“未经背驰确认”。这只是诊断标签，不属于 R 的确认字段。离线工具汇总 BTC/ETH 六组固定行情的重合率，作为后续是否修改 R 的依据。

### 7. 验证

- 独立样例 `tests/fixtures/chanlun/signals/`：输入为已完成部件加上逐根 MACD 柱值，与 MACD 计算解耦；预期按规则人工推导。
- MACD 本身另用平台脚本与内置 `ta.macd` 逐根对照。
- 生成器沿用同核验证模式，从正式文件抽取 CORE 与信号区。

## Risks / Trade-offs

- [背驰口径在原文中有多种表述] → 先冻结规则与样例；每条分列 author-body 与 engineering，存疑的条件放进研究信息，不作为硬门槛。
- [MACD 用图表周期计算，而层级不对应时间周期] → 在文档中写明这是工程约定；面积只用于同层同参数的相对比较。
- [信号与 R 的结构差距会让第一类点与 R 端点不一致] → 用诊断显示并统计，不在本变更里静默修正。
- [新增数组和标签可能触及资源上限] → 纳入统一预算；超限时整层停止信号确认并提示，形态内核不受影响；重新做 5,000 根三层压力验收。
- [提醒误报会直接影响用户操作] → 提醒只针对确认信号，并在平台用实时 K 线验证一次只发一条。

## Migration Plan

- 在 `chanlun_original.pine` 内加信号区，默认开启确认买卖点显示，提醒默认关闭。
- 形态 CORE 的哈希须与本变更前一致，或其差异仅限新增的只读接口，并重新跑全量共享内核验证。
- 回滚：信号区整体可由一个总开关关闭；关闭时形态输出与上一版一致，由“关闭全部信号显示”场景验证。

## Open Questions

- 各层买卖点的默认可见性（例如默认只显示 L1、L2）在渲染验收时按标签密度确定，不影响规格与任务拆分。

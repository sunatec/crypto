## Context

- 主分析只取 `--start`~`--end` 窗口；顶层结构起点 S 由 `directionalTopSpan` 取窗口内全局极值，`tree.primary.points[0]`。
- 父级身份由 `deriveParentDegree` 按「反弹回撤大跌的比例 + 子浪性格」在 X / B / 新推动之间排名，`renderParentRole` 在大跌子浪已验证时把首位标为「✅ 主选」——这只说明窗口内的子浪成立，不说明它在更大级别里的角色成立。
- `candle-cache.getCandles(product, 86400, 'all', end)` 已能发现上市首日并缓存全部日线；`transformCandles` 用 `TIMEFRAMES['1w'|'1m']` 做 UTC 周一起/自然月聚合；`maxInternalRetrace` 已实现 §3.3 的「段内已创极值 → 之后反向极值」最大回撤（绝对价差）。
- 报告按三条主题轴组织（`wave-count-tree` 规格）；「整段在更大结构里的角色」归轴①子块。

## Goals / Non-Goals

**Goals:**
- 让读者看到窗口结构在全部历史中的位置，以及对每个可能的上一级前段，§3.3 给出什么判断。
- 报告诚实声明数浪范围；父级身份不再因窗口内子浪验证而显示为「✅」。
- 背景失败不影响主分析；背景开关不改变任何既有输出。

**Non-Goals:**
- 在周线/月线上完整数浪、要求日线主选是周线某浪的子浪（书 §3.10 的完整自上而下，另立变更）。
- 用背景改变数法排名或父级候选排序。
- 股票的大级别背景（无缓存、取数配额受限）。

## Decisions

### 1. 数据：全部日线 → 本地聚合周/月线

`main()` 在 Coinbase 路径、背景开启时调用 `getCandles(product, 86400, 'all', end, {refresh})`，再 `transformCandles(…, TIMEFRAMES['1w'])` 与 `['1m']`。不改用其他交易所的原生周/月线：跨交易所极值不同，会与日线端点对不上。全部历史取数结果带 `fetchErrors` 或抛错时，背景为 `{available:false, reason}`。

背景计算做成纯函数 `buildHigherDegreeBackground({daily, structure, listingTs})`，取数与计算分离，便于用合成日线测试；`main()` 只负责取数与挂载。

### 2. 级别阶梯：从 S 向前的「逐级更深」前段起点

设窗口顶层结构起点 S、终点 E（下跌结构：S 为高点、E 为低点）。

1. 周线序列截到 S 所在周之前（不含该周），在其上 `detectPivots(lookback=1)` + `anchorBoundaryExtremes`。S 所在周可能含窗口外更高的价格，所以不用该周 K 线，而以 S 本身（价格、时间）作为前段终点。
2. 从 S 向前遍历周线低点枢轴，维护「迄今最低」，得到逐级更深的低点序列；只考虑 `price < E.price` 者（窗口下跌未超过 100% 回撤该前段；被完全回撤的前段不可能是其所修正的那一浪）。
3. **按 §3.3 分级**：沿该序列往前推时，若前段 `Lk → S` 的内部最大回撤（价差或百分比任一口径）比上一级更大，说明前段纳入了更大的一次修正，进入更高一级；否则仍属同一级。每一级取组内最深的低点作为前段起点。
4. 追加 §3.12 的价格 0 级（起点 = 上市首日之前，价格 0），作为最高一级；上涨结构的前段为下跌，0 级不适用，省略。
5. 设上限 8 级作为保险，超出时注明省略数量。

原型验证（BTC-USD 全部日线，S=126296@2025-10-06，E=57717.55）：「迄今最低」低于 E 的周线低点有 19 个，若每个都算一级，2023 年会出现多个只差几千美元的级别，且上限会截掉最深的几级。按第 3 步分级后只剩 4 级，组内取最深分别为 49050（2024-08）、15460（2022-11）、3129（2018-12）与最早一级；窗口下跌 68578（54%）对后两级出现「价差口径超过、百分比口径未超过」（内部最大回撤 53540 / 78%），正是决策 3 需要并列两种口径的情形。

上涨结构整体镜像（高点枢轴、迄今最高、`Hk.price > E.price`）。

- 备选：只取一个「上一级」前段。否决——前段属于哪一级本身就是要回答的问题，单选一个等于替读者做了未经验证的级别判断；阶梯把每一级的证据都摆出来。

### 3. 每一级的度量：两种口径并列

| 字段 | 绝对价差口径 | 百分比口径 |
|---|---|---|
| 前段幅度 | `S − Lk` | `S / Lk − 1`（0 级为 —） |
| 窗口结构回撤比 | `(S − E) / (S − Lk)` | `ln(S/E) / ln(S/Lk)`（0 级为 —） |
| 前段内部最大回撤 | `maxInternalRetrace`（价差） | 同一遍历中按「回撤 ÷ 当时已创高点」取最大 |
| §3.3 超过？ | `S − E` > 内部最大价差回撤 | `(S − E)/S` > 内部最大百分比回撤 |

内部回撤在周线枢轴 `Lk … S` 上计算（0 级为上市首日起的全部周线枢轴）。书 §3.3 未规定口径；跨多年时价格量级相差几十倍，绝对口径会被近期价位主导，百分比口径对应 §3.9 对数坐标的「涨跌幅度」。两者都报，结论不同时明示「口径不一致」。

### 3a. 背景中的疑似扎针

原型发现 Coinbase BTC-USD 日线 2017-04-15 开 1173.13、收 1178.85、低 **0.06**——书 §3.15 所说的乌龙针。不处理时它成为「历史最低」，并把最深一级前段起点拉到接近 0。背景计算前对全部日线做一次检测：低点不足 `min(开, 收, 前一根低, 后一根低)` 的 50%，或高点超过 `max(开, 收, 前一根高, 后一根高)` 的 2 倍，视为疑似扎针，把该极值截到参考价，并在背景中披露。

- 只作用于背景，不改窗口主分析的 K 线；主分析的扎针检测与 `--ignore-thin-spikes` 属于第 7 条 B，另立变更。
- 书以成交量区分可忽略与否，但日线成交量是全天的，无法单独度量那一笔；阈值取得很宽（偏离 50% / 2 倍），只抓明显的数据错误，正常闪崩（如单日 -20%~-30%）不会触发。

### 4. 月线概览

- 上市首日：`listingTs` 当日日期与开盘价；历史最高/最低：取自全部日线（精确到日），附日期。
- S 的位置：S 是否为历史最高（下跌结构）/最低（上涨结构）；否则给出距历史极值的百分比。
- 月线摆动：月线 `detectPivots(lookback=1)` 后的枢轴序列，报告列最近 10 个，JSON 全量。

### 5. 呈现

- 报告开头（元信息块后）一行「数浪范围」声明；JSON 顶层 `scope: {startUtc, timeframe, startPrice, startIsWindowExtreme, topDown:false, note}`。
- 轴①在「在更大结构里的角色」之后新增子块「大级别背景（周线/月线）」：概览 3 行 + 阶梯表（每级一行：起点、前段幅度、回撤比 价差/百分比、内部最大回撤、§3.3 结论）+ 一句话读法。
- 简报（4 条）不新增条目，只在第 1 条末尾附「大级别背景见轴①」。
- `renderParentRole`：首位标签一律「⏳ 暂定主选（未经大级别数浪验证）」，表下附背景摘要一句（不可用时写明原因）。JSON 中父级候选的 `verificationStatus` 维持原值，不改既有字段。
- JSON 顶层新增 `background`（可用时含 `listing`、`extremes`、`monthlySwings`、`ladder`；不可用时 `{available:false, reason}`）。

### 6. CLI

`--background on|off`，加密货币默认 on；股票强制 off（只输出范围声明并注明未生成背景）。`--refresh` 一并作用于全部历史取数。

## Risks / Trade-offs

- [§3.3 判断被读成定论] → 文案沿用书的「可假设」，并始终与「父级身份为推断」同屏出现。
- [周线 lookback=1 的枢轴对级别敏感] → 阶梯只用「逐级更深」的低点，对小枢轴不敏感；内部最大回撤在周线上取，较日线略浅，报告注明「周线枢轴」。
- [首次运行变慢] → 仅首次约十几页日线请求，之后命中缓存；可用 `--background off` 跳过。
- [S 所在周含窗口外更极端价] → 不用该周 K 线，直接以 S 作为前段终点（决策 2.1）。

## Migration Plan

新增字段与报告子块，旧字段不变；`--background off` 回到仅多一行范围声明的输出。父级候选表的「✅ 主选」字样变为「⏳ 暂定主选」，相关黄金/渲染断言需更新。

## Open Questions

- 疑似扎针阈值（50% / 2 倍）是工程设定，书无量化标准；若日后主分析也做扎针检测，两处应共用同一判定。

- 背景证据日后是否参与父级候选排序（例如 §3.3 在所有级别都未超过时降低「新推动」读法）——留待阶梯在真实品种上观察后再定。

## Why

书 §3.10 要求从月线、§3.12 要求从价格 0 起自上而下数浪，但引擎只从用户给的 `--start` 窗口、以窗口内极值为起点，向下验证到 4h/1h，从不向上看。报告里大跌在更大结构中的角色（X 连接浪 / B 浪 / 新推动）只由窗口内的回撤比例推断，读者无从判断它在全部历史中处于什么位置。K 线缓存（`candle-cache`）已就位，拉取全部历史只在第一次有成本，现在可以补上大级别背景。

## What Changes

- 加密货币（Coinbase）分析时，经缓存取该品种自上市首日起的全部日线，聚合成周线、月线，生成「大级别背景」：
  - 月线概览：上市首日与首日价格、历史最高/最低、月线主要摆动。
  - 级别阶梯：以窗口顶层结构的起点为终点，向前在周线上找出逐级更深的前段起点（只取未被窗口结构完全回撤的那些，外加 §3.12 的价格 0），对每一级给出：窗口结构对该段的回撤比，以及按 §3.3「是否超过该段内部任何一次回撤」的判断，绝对价差与百分比两种口径并列。
- 报告开头与 JSON 声明数浪范围：从哪天、哪个周期、以哪个价格起数，是否按 §3.10/§3.12 自上而下验证。
- 父级身份（X / B / 新推动）仍为推断，报告中不再标「✅ 主选」，改标暂定并附大级别背景摘要；背景只作证据展示，**不改变任何排名或主选**。
- CLI 新增 `--background on|off`（加密货币默认 on）；取数失败时背景标为不可用，主分析照常输出。
- 股票本次不做大级别背景，只输出数浪范围声明。
